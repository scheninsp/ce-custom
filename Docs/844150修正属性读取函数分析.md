## 结论

此前文档只记录了对 `+844150` 的调用点，没有保存该函数本体。本次从当前游戏文件提取并反汇编了完整函数：

- 文件：`D:\Games\Victoria3\Victoria 3\binaries\victoria3.exe`
- 文件大小：`96374904` 字节
- SHA-256：`5FE215DB840E311541950E2B57689A1C67C3FA4C85DAF51949C433430A125E21`
- 模块基址假定为 `0x140000000`
- 函数范围：`[victoria3.exe+844150, victoria3.exe+84420A)`
- 入口绝对地址：`0x140844150`

这个函数**不是修正值计算器**。它接收一个属性容器、一个输出地址和一个 16 位选择值，在容器内部的哈希表中查找该选择值对应的属性槽；找到后把槽中的 64 位值写到输出地址。找不到时使用容器的默认槽，默认槽也无效时使用一个全局默认值。

因此，候选数量调用点中的业务流程应理解为：

```text
modifierRaw = PropertyContainerRead(statePropertyContainer, selector=0x97)
quantityRaw  = baseRaw * (100000 + modifierRaw) / 100000
```

`+844150` 本身不遍历生产方式、不执行多个修正相加，也不进行定点乘法。它只是按选择值读取一个已经存储或已经汇总好的属性值。属性 `0x97` 的正式业务名称仍需从属性注册表或调用方对象类型中继续确认。

## 算法还原

### 1. 用选择值计算桶索引

选择值是 16 位整数，函数按低字节、高字节分两次执行 FNV-1a 风格的哈希：

```text
hash = 0x811C9DC5
hash = (hash xor (selector       & 0xFF)) * 0x01000193   // 32 位回绕
hash = (hash xor ((selector >> 8) & 0xFF)) * 0x01000193
bucket = sign_extend(hash) & container->bucketMask
```

汇编中的 `lea index*3` 再乘 8，等价于 `index * 24`。因此哈希表的每个桶槽大小为 24 字节。

### 2. 在桶内查找选择值

函数从桶首项开始，以 24 字节为步长比较：

```text
entry.selector == selector
```

每个项的 `+0x04` 是该桶链或桶内有效范围的计数/边界字段，`+0x08` 保存用于匹配的 16 位选择值。找到匹配项后停止；如果当前桶没有匹配项，则转到默认项位置。

结合指令能够确认“桶内线性查找”和“24 字节项大小”，但尚不能仅凭此函数确定 `+0x04` 的 C++ 类型，也不能把它直接命名为链表长度。

### 3. 找不到时选择默认项

未匹配时，函数使用：

```text
defaultIndex = container->bucketMask + container->defaultIndexByte + 1
defaultEntry = table[defaultIndex]
```

随后又计算一个紧邻的末端项指针，用于判断 `defaultEntry` 是否等于无效/末端标记。

### 4. 从项中取值并写出

有效项的 `+0x10` 被当作一个指针，再读取该指针指向的 8 字节值：

```text
if entry != endMarker:
    valueHolder = entry + 0x10
    value = *valueHolder
else:
    value = *(globalDefaultValueHolder at module+43DAE78)
*outValue = value
return outValue
```

如果默认项等于末端标记，函数会使用 `module+43DAE78` 指向的全局默认值容器。这个全局位置在函数中只作为兜底读取源，不能据此判断默认值的业务名称。

## 与候选数量计算的关系

候选数量调用点传入的选择值是运行时全局中的 `0x97`。因此目前可以把调用关系具体写成：

```text
container  = state 的数量修正属性容器
modifier   = ReadProperty(container, selector=0x97)
factorRaw  = 100000 + modifier
quantity   = trunc_toward_zero(goods.baseQuantity * factorRaw / 100000)
result     = max(quantity, MINIMUM_GOODS_TRADED_QUANTITY)
```

本次反汇编说明了 `ReadProperty` 的查表过程，但还没有证明 `0x97` 的属性注册名称，也没有展开属性容器在更早阶段如何生成或汇总各项修正。要继续确认业务来源，需要追踪构造该容器的代码、属性注册表，以及 `0x97` 在其他调用点中的对应定义。
