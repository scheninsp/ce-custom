# 这个 ”本地市场有效供给 S  “ 和 ”### 贸易项评分计算的其他条件限制
- 一方向的市场贸易总量受其反方向贸易总量的限制
当本市场方向量超过外部反方向可承接量的两倍时，候选贸易增减项直接无效。
L定义为本市场当前贸易项的方向的贸易量
L > 2(W-O) ，W 和 O 与前面相同，分别是 反方向本地市场贸易量 和 反方向世界贸易量。” 中的 L, W, O 都不相同吗？他是个额外的变量吗？和这些有什么关系？

是的，**`S` 是额外计算的量，和 `L、W、O` 含义不同，但部分数据来源重合。** 它不是额外的配置参数。

以你关心的**进口候选**为例：

| 变量 | 含义 |
|---|---|
| `S` | 本市场该商品的有效供给，用于供给耗尽判断和短缺评分 |
| `L` | 本市场进口量，增加模式包含候选新增量 `q` |
| `W` | 世界出口量 |
| `O` | 本市场出口量 |
| `W-O` | 本市场以外的出口量 |

你引用的最后一句把 `W、O` 写反了：应为 **`W` 世界反方向量，`O` 本市场反方向量**。

它们的关系，在[静态报告](/D:/cebuild/ce-custom/Docs/2026-10-3-process1/intermediates/goal3_static_disassembly2.md:132) 中可以直接对照：

```text
S = M[228] + X[00] + X[F0]
O = M[2D8] + X[00] + X[F0]

因此：
S - O = M[228] - M[2D8]
```

这里 `M` 是本市场商品表，`X` 是评估上下文表，偏移为十六进制。**`S` 和 `O` 共享上下文调整项，但基础表不同，所以不能视为同一个量。** 基础表的具体组成尚未全部确认，也不能据此直接断言 `S=国内产量+进口量`。

两个判断分别关注不同问题：

- **`L > 2(W-O)`**：外部出口贸易量是否足以支撑本市场进口？超过上限，直接判候选无效。
- **减少进口时 `S-q <= 0`**：撤掉这批进口后，本市场是否将失去有效供给？满足正补助差等条件时，提高这批进口的保留评分。

因此，减少进口时扣掉 `q` 的是**本地有效供给 `S`**，不是世界出口量 `W`。这正是原文中需要纠正的地方。

## S 公式的当前确认边界

九州 UI 已经核实 `州[58]` 是国际市场接入度，州[498] 是该州贸易中心出口量，硬木的州[C8] 是该州贸易中心进口量。因此对当前观察到的市场对象，下面两点可以提升为高可信业务解释：

```text
M[228] = Σ当前市场各州(州侧供给/进口表[C8] × 州[58]) + 条约商品转入表 M[3C8]
M[2D8] = Σ当前市场各州(贸易中心出口表[498])
```

这里的求和范围是**当前市场所属州**，不是全世界所有州。州[C8] 在硬木样本中等于进口量，但纸张等商品仍应把它写作“州侧供给/进口表”，不能仅凭一个商品把整张表断言为纯进口量。

对 `S = M[228] + X[00] + X[F0]`，目前可以确认的是上下文结构，而不是 `X` 两项的最终 UI 名称：

```text
X[00] = 当前州条目的进口净调整表副本
X[F0] = 市场分组进口净调整表副本 - 当前州条目的进口净调整表
S    = 市场基础供给 M[228] + 两张临时评估修正表中该商品的值
```

直接证据来自 `+11FD370`（[反编译](../../Output/market_tables/context_ghidra/function_11FD370.c)）：

```text
X[00] <- entry + 0x60
X[50] <- entry + 0x10
X[A0] <- 市场分组出口调整表，再减 entry + 0x10
X[F0] <- 市场分组进口调整表，再减 entry + 0x60
```

其中 `+0x60` 和 `+0x10` 是州条目携带的进口、出口净调整表；`+11FD230` 构造时初始化为空。`+11FD470` 在方向 0 增加贸易时，向 entry+0x60、市场分组表和全局调整表分别加 q；方向 1 使用 entry+0x10 和对应出口表。`+11FAF20` 撤销贸易时向同一组表减 q。`+1027E20` 遍历源表调用减法函数 `+1027A40`，所以这里是减去当前州的调整量，不是相加。

因此 `X[00]` 是本批次当前州已经执行的进口净变化，`X[F0]` 是该市场分组累计进口净变化扣除当前州部分。它们不重复计入基础进口存量或条约量；净变化可以为正、负或零。

当前最严谨的完整表述是：

```text
S = 市场重建得到的基础供给 M[228]
    + 本批次当前州的进口净调整量
    + 本批次该市场其余州的进口净调整量
  = M[228] + 本批次该市场累计进口净调整量
```

这是静态构造和增减写入路径共同支持的业务解释，分析摘录见 [供给上下文](../../FakeCode/2026-10-4-process2/trade_supply_context.md)。本次没有继续游戏或修改 CE 断点。这里的 S 不自动包含尚未执行的候选 q；减少候选的短缺计算另有 S-q 操作。注意基础供给的州[58]缩放与临时进口调整不同：此处增减表直接写入 q，未再次乘州[58]。

## M[418] 推测高概率置信解释
对应的 M[418] 是转出方向表。
这里的“转出”指的是：**本市场通过外交条约向另一方提供商品**，不是所有导致商品被消耗或离开市场的行为。

按目前恢复的写入路径：

| 项目 | 是否计入 `M[418]` |
|---|---|
| 九州本地建筑消耗 | 不计入这张表 |
| 九州贸易中心出口 | 不计入这张表，记录在州[498]，再汇总到 `M[2D8]` |
| 外交条约商品出口 | 计入这张表，经条款有效性检查和数量倍率计算后累加 |

而且 **`M[418]` 是整个当前市场的汇总，不是九州专属统计**。

它被加入市场需求侧，是因为条约要求本市场提供这批商品，相当于额外增加购买需求。代码没有直接从 `M[228]` 的供给里扣除它。

因此应区分：

```text
M[2D8]：市场内各州贸易中心的出口总量
M[418]：市场通过外交条约转出的商品量
M[3C8]：市场通过外交条约接收的商品量
```

上述是已恢复路径支持的分类；具体条约类型和倍率仍有反编译缺口。之前笼统说“转出方向表”不够清楚，称为“条约商品转出表”更准确。


## 游戏内 UI 核实
州[58]：九州贸易中心的国际市场接入度，UI显示为 99%。
纸张的州[498]是纸张在九州贸易中心的出口货物数量。对应占用的贸易容量是52.
纸张的州[C8]是九州造纸厂的周生产量，UI显示为2.4K.
硬木的州[C8] 为硬木在九州贸易中心的进口货物数量。对应占用的贸易容量是53.
所以硬木的州[498]为0是出口量为0，已核实。
硬木在九州的造船厂消耗580，海军后勤中心消耗5.38，因此州[498]不是九州硬木的总消耗值。
但是州[C8]应当是商品的总供应值，它=本地生产+本地进口值。

所以
```
M[228] = 各州[C8]按州[58]折算后的总和 + 条约接收商品量
M[2D8] = 各州出口表[498]的总和
```
M[228] 应当是 sigmaX(当前市场X州总供应该商品的量 x 当前市场的X州的国际市场接入度)
M[2D8] 应当是 sigmaX(当前市场X州出口该商品的量)


## 仍是上面的推测的
M[3C8] 是外交条款带来的商品转入供给汇总，高可信对应条约商品转移。
