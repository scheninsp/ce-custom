### 1. 最终公式及顺序

以通常数值范围内的实数写法表示，方向 `d=0` 为进口，`d=1` 为出口：

```text
A(s,g,d) = 100 + A_production + A_charter + A_prestige
                   + A_privilege + A_port + A_bloc + A_religion
                   + A_embargo + A_war + A_interest

M(s,g,d) = m_trade + m_goods(g) + m_direction(d)
                   + min(C * k_capacity, cap_capacity)
                   + 0.25 * prestige_merchant_share

W(s) = s.field68 < 1 ? s.field68 : 1

TA(s,g,d) = max(1, A(s,g,d) * max(0, 1 + M(s,g,d)) * W(s))
```

s+0x58 更可能是普通市场接入度，s+0x68 是由它进一步计算出的国际市场接入度

**全部百分比项先相加，再统一乘以点数合计；接入度是最后另乘的因子。**
市场首都、自由贸易、对外贸易原则等已经包含在 `m_trade` 中，不能再次单独乘一次。
商品特有倍率 `m_goods(g)` 是代码额外读取的一项，原配置清单没有明确列出。
最终下限是 **1 点而非 100 点**：根函数写缓存前取 `max(result,100000)`，定点比例为 `S=100000`。

严格整数实现：所有数量、点数、比例均以 `S=100000` 为一单位；
`mul(x,y)` 普通分支为 `trunc_toward_zero(x*y/S)`，`div(x,y)` 为 `trunc_toward_zero(x*S/y)`。
各加项分别计算、取整后再累加；不能只在最终一次取整。大数采用原代码商余数分拆分支，
极大分母还存在 `x/(y/S)` 路径，实数公式不保证在该范围逐位复现。
`NormalizeAdvantage` 另外保留极小非零乘积的正负一整数单位保护，再乘独立乘数；
当前上下文上下界为 int64 最小/最大值，负百分比倍率钳制到零。

### 3. 出口生产的三个点数加项

设 `P_world(g)` 为世界商品生产量；`P_area(s,g)` 为所属市场区域商品生产量；
`access58` 为州相关对象 `+58` 的定点接入字段。
整个分支仅在 **出口且世界生产量 > 0** 时执行。

```text
A_production = 200 * (P_area / P_world) * access58
A_charter = P_area > 0 && P_charter > 0 ? 50 * P_charter/P_area : 0
A_prestige = prestige_share > 0 ? 100 * prestige_share : 0
```

生产份额通过 `+10276F0` 从世界 `+5F8` 商品表和市场区域表读取。
`+CFCBF0` 按州的 `+B48` 市场引用查市场区域表；`+CFCCD0` 读取其公司生产子表。
威望份额 `+1027410`：商品总量为分母、商品分组记录中的后三个数量槽合计为分子。
这不是奢侈品商品类型判断，而是同一商品中威望商品的数量份额。
关键点数入槽调用位于 `+12264E5/+12266E7/+122681F`。

### 4. 外部市场份额与外交点数

先取反方向 `o=1-d`。世界反方向总量 `G` 由 `+11F9790` 读取，
本市场反方向总量 `L` 由 `+1254850` 读取。只有 `G>0` 才进入外部市场遍历，
并排除与当前市场相同 ID 的条目。

对每个外部市场 `j`，代码不是始终用 `Q_j/G`：

```text
N_j = 方向相关的市场关联商品生产量（出口 +CFCE60，进口 +CFCDE0）
w_j = clamp(L>0 && N_j>0 ? N_j/L : Q_j,o/G, 0, 1)
```

其中 `+CFCE60` 从本市场区域 `+650` 按目标市场 ID 查表；`+CFCDE0` 从目标市场
`+668` 按本市场 ID 查表。代码和字段可确认上述读取关系；两个关联生产表的完整更新机制
没有在本次恢复，因此不把 `N_j` 简化为普通“对 j 的贸易量”。
opcode `+1226B88/+1226B8B/+1226B94` 判断两个分母条件；
`+1226C62` 回退调用反方向数量读取；`+1226D45..+1226D67` 裁剪至 `[0,1]`。

```text
A_privilege = sum_j(100 * w_j * privilege_j)
A_bloc     = sum_j(bloc_bonus * w_j * eligible_same_bloc_j)
A_religion = sum_j(religion_bonus * w_j * same_state_religion_j)
```

集团和同国教属性只有 **属性值大于 0** 才加入；负的此类 `_add` 属性不会在这里形成惩罚。
集团属性取自州所有者所属集团；同国教属性取自 `s+18B0` 的属性集合。
真实判定调用分别为 `+C35550`、`+13CFCC0`；国教比较为国家对象 `+C90` 指针相等。

条约港另有份额，不能直接替换成同一个 `w_j`：

```text
A_port = sum_j(200 * T_j,o/G), 只纳入 T_j,o>0 的条目
```

`T` 为 `+CFCB90/+CFCB30` 查询的条约港方向商品量；进口读取条约港记录 `+148` 子表，
出口读取 `+F8` 子表。该分支本身没有 `[0,1]` 裁剪，且位于 `w_j>0` 的市场循环内。

每个市场的负项／利益项严格按以下互斥分支选择：

```text
if 被禁运:         contribution_j = -100 * w_j
else if 交战:      contribution_j = -75 * w_j
else:              contribution_j = tier_bonus(d,j) * w_j
```

因此**除了禁运优先于战争，利益等级加成也不会与该市场的禁运或战争惩罚同时出现**。
rank=0 且本国具有 `country_no_advantage_loss_from_lack_of_interest_bool` 时跳过利益项。
代码读取利益对象 `+1D8`（出口）或 `+1E0`（进口）；rank 在 `+1D0`。
配置六档的进/出口点数分别为 `(0,-50)`、`(0,0)`、`(10,10)`、`(25,25)`、
`(50,50)`、`(100,100)`。对应分支 opcode：`+12277F8..+122785A`。

### 5. 百分比倍率的精确来源

`FillGoodsDirectionContext` 末尾读取三类属性中的前两类：

1. `m_goods(g)`：按商品 ID 索引类型编号表 `+1048`，步长 28 字节，读取条目 `+10` 的 uint16 编号；opcode `+1228469/+12284A2/+12284B9`。
2. `m_direction(d)`：进口 `state_import_advantage_mult`，出口 `state_export_advantage_mult`。
3. `BuildMarketTradeFraction` 读取通用 `state_trade_advantage_mult`。

以上均使用操作类型 **2**，所以相加，不是三次独立相乘。
商品动态修正键的字符串构造未在当前主链中直接出现，本节以其确定的类型表槽位标识，
不猜测完整脚本键名。

威望商船：贸易中心存在、虚拟有效性检查成立且 `level>0` 时，
`+E3FC40` 取得商品投入表，商品注册对象 `+F60` 对应商船；`+1027410` 计算威望占比。
只有占比 > 0 才加 `0.25*占比` 到百分比槽。这里有一个未静态解析的虚拟有效性调用，
不能声称已经恢复建筑有效性检查内部全部条件。

容量：

```text
C = int32(s+1D58)
m_capacity = min(C * state_trade_advantage_from_capacity_add,
                       state_max_trade_advantage_from_capacity_add)
```

`+122BF50` 调用 `FUN_141229c50`（`+1229C50`），把整数结果存入 `+1D58`。
后者结算容量数值上下文后 `/100000` 向零取整，通常至少 1；不允许贸易时返回 0。
本次原始导出在 [Ghidra 容量函数](../../Output/2026-10-4-process2/absolute_trade_advantage/ghidra/function_1229C50.c)。
优势链直接使用这个已缓存整数，不重新获取实时未取整容量。

基础 `k=0.0005`，所以 **每 1 容量 +0.05%，每 100 容量 +5%**。
基础上限 20%；四项金融科技各增加 5 个百分点，全部解锁后通常为 40%。
容量项只有上限 `min`，该分支没有下限 `max(0,...)`。
九州既有 UI 样本为 229 容量、+11%（上限35%），对应 `229*0.0005=11.45%`，
与 opcode 一致；Wiki 的“每100容量 +0.5%”差十倍。

## “W(s) = s.field68 < 1 ? s.field68 : 1  " 这里 s.field68 的业务含义能推测吗

可以，**`s.field68` 很可能就是州的“国际市场接入度（World Market Access）”缓存值**，可信度较高。

依据有三点：

- 绝对优势函数读取 `s+0x68`，对应的说明文本是 `ADVANTAGE_FROM_WORLD_MARKET_ACCESS`，即“由于国际市场接入度”。
- 每周贸易调整预算函数 `+12295A0` 也读取同一字段，作为最后的乘数。这与“国际市场接入度降低每周贸易调整预算”的机制一致。
- 已分析的接入度计算函数 `+1210600` 检查世界市场枢纽、连通路径和封锁，符合这个字段的用途。

因此公式可以用业务名称写成：

```text
W(s) = min(州的国际市场接入度, 1)
```

例如接入度为 80%，就把此前算出的绝对优势乘以 `0.8`；达到或超过 100% 时不再增加优势。这里限制的是**国际市场接入度造成的最终缩放**。

另外，**`s+0x58` 更可能是普通市场接入度，`s+0x68` 是由它进一步计算出的国际市场接入度**。`+1210600` 读取 `+58` 时使用的提示明确为“来自市场接入度”，之后再检查国际路径并应用封锁影响。因此两者正常情况下可能相等，但断路或封锁时可以不同。

尚缺的直接证据是找到“把 `+1210600` 的结果写回 `s+68`”的指令。目前可以标注为“国际市场接入度缓存，强证据推断”，还不能称为已完整确认其写入链。
