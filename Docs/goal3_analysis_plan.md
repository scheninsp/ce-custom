# goal3：九州硬木进口数量的分析方案

## 目标与主要思路

找出九州贸易中心的硬木进口数量由哪些函数决定，并还原能够解释实际结果的算法：商品如何被选中、容量如何增加或转移、容量如何换算成数量，以及利润、补助等因素在哪里生效。

从当前容量断点进入，沿着“上层调度 → 商品选择与评分 → 容量调整 → 数量更新”追踪。以关闭相关 UI 后仍运行的游戏逻辑为主线，不再从显示数值的临时内存向上追。

当前更值得验证的假设是：**每周在有限操作次数内，逐次增加、减少或替换贸易，最终形成各商品的容量份额**。不能直接假设每周把全部容量按利润比例重新分配，也不应预设最终答案只在一个函数中。

本文件是静态资料分析与后续执行方案，尚未连接 CE、继续游戏或验证运行时算法。

## 执行步骤

### 1. 固定基线，确认对象身份

- 保存同一存档、游戏日期、版本、MOD、补助档位及 UI 数据，记录模块基址；代码地址同时记录为模块偏移。进程重启后重新定位对象，不能复用旧堆地址。
- 核对九州对象的身份，并分别读取 `+1D58`、`+1D5C`。通过存在剩余容量的样本、字段写入来源和比较分支确认二者含义。
- 核对硬木商品 ID 及市场身份，以九州硬木进口为追踪目标。
- 确认当前数据是否仍为九州 330、日本合计 830。旧 UI 数据仅作校验线索，不强求后续断点复现旧数值。

产出：一张对象、字段、商品与方向的对应表，以及可重复使用的基线存档。

### 2. 先画出当前函数的决策和更新路径

- 补全 `+11FD470` 的所有分支和返回路径；现有前后 100 条窗口在函数中途结束，不能据此下完整结论。先复用 `trace_capcity8.md` 的较完整反汇编，再核对当前机器码。
- 区分容量未满、容量已满、替换成功、增加失败等路径；逐一记录条件、调用参数、修改对象和返回值。
- 优先检查 `+11FD370`（前置候选处理）、`+11FAF20`（比较之后的处理）、`+11FBC80`（后续是否成功的判断），以及 `+1027970`、`+122BED0`、`+122BF50` 的实际作用。括号中的描述是追踪用途，不是已确认函数名。
- 核对 `RDI+0xB0`、`RDI+0xF8`、`RDI+0xB8` 及 `center+0x1D88` 的对象类型、商品关联和方向含义；检查当前命中的是否确实为硬木，而非九州其他商品。

产出：当前函数的简短伪代码，明确哪些输入已经由上游算好、哪些决策在本函数完成。

### 3. 向上追商品选择，向下找实际写入

- 验证 `7FF777E0D219` 调用点；栈扫描结果是启发式候选，须结合函数栈布局或实际命中确认。旧记录存在步长 `0x140` 的条目遍历线索，继续追条目创建、候选排序/筛选、随机选择及循环终止条件。
- 区分“贸易容量”“每周允许的调整次数”“商品数量”三个量。若 `[rdi+4]` 是操作预算，追其初始值与扣减规则，而不是用它解释硬木 330。
- 在下游记录每次调用的键、增量和写入前后值，确认 `center+1D88` 是否按商品保存容量，以及进口、出口如何区分。找到真实模拟状态的写入后，再对该位置设置范围有限的写入监视。
- 若数量没有独立持久字段，则继续追底层容量/贸易记录如何派生出数量，最终说明派生公式即可；无需坚持找到保存 330 的稳定地址。
- 若当前函数只是提交已算好的结果，就沿输入来源回溯到选择和计算位置；容量字段写入函数仅作为辅助入口，不把总容量重算误认为商品分配算法。

产出：一条有调用与读写证据支持的“调度 → 选择 → 容量变化 → 数量结果”函数链。

### 4. 抓住一次完整周更新，建立数值对应

- 关闭贸易 UI，围绕游戏内周更新前后采样，验证这些函数是否仍执行，以及实际更新频率。不能用现实经过秒数或一次断点命中代替周更新证据。
- 使用九州对象条件筛选，确认商品 ID 后再增加硬木条件。记录一整轮中硬木及被替换商品的选择顺序、评分、操作预算、容量和数量的变化，避免只截取一次调用。
- 同时记录价格、补助、关税、短缺、相对优势及限制条件中实际进入算法的值，区分“目标数量”和最终成交/汇总数量。
- 保留原始整数和解释后的数值；反汇编中的 `100000` 是定点缩放线索，须逐字段确认位宽、符号、比例与舍入，不能把所有字段统一除以 `100000`。

产出：至少一组可以从输入、分支和增量推到最终数量的完整样本。

### 5. 用少量对照实验排除错误解释

- 从同一基线存档重放，先做一次不改参数的对照，再分别测试硬木进口补助的无、`0.25x`、`0.5x`、`1x`。每组到同一游戏日期比较，并记录其他市场输入变化；不把档位直接当作实际补助金额。
- 比较容量未满与已满情形，验证“直接增加”和“替换旧贸易”的不同条件；观察一次成功与一次失败的操作预算扣减。
- 同时观察紧接着的一周和跨越保护期的结果；若存在随机选择或市场反馈，重复基线并比较完整轨迹，避免把一次不变误判为没有影响。
- 只在现有样本不足以区分公式时增加实验，例如比较第二种商品的容量到数量换算。优先改变一个因素，避免同时改价格、容量、补助和代码。

产出：能够支持或否定利润比例分配、逐次调整、替换门槛、补助双重作用等解释的对照记录。

### 6. 还原算法并验收

- 将实际指令整理为可读伪代码，分别说明评分、选择、增减/替换、每周预算、保护期、容量到数量的换算，以及最终限制和舍入；未知部分明确标注。
- 用抓取的原始输入离线复算一次完整更新，再用另一周或另一补助档位的独立样本检验。误差必须能由已确认的舍入、随机输入或更新阶段差异解释。
- 汇总所有商品的容量占用与已用容量核对；在相同日期、方向和统计口径下，再核对各贸易中心硬木数量与日本市场合计。不要把不同商品的实物数量直接相加当作容量。

完成标准：能指出关键函数和写入点，解释一轮更新为什么得到该硬木进口数量，并能用另一组样本验证。仅找到一个读取 126 或显示 330 的函数不算完成。
