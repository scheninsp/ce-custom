# 州贸易调整函数的候选准备函数

来源：`victoria3.exe+131D540` 附近反汇编，以及其调用的 `+122AC50`、`+122B320`。

本文说明 `TryAdjustStateTrade(+11FD470)` 使用的 `e.remove` 和 `e.add` 是怎样产生的。这里的“候选”是单个商品加方向等字段组成的临时结构，不是商品列表。

## 一、总体调用链

```text
UpdateStateTrades(+131C2B0)
    └─ 为每个州建立条目
       └─ PrepareCandidates(+131D540)
          ├─ SelectReductionCandidate(+122AC50) → entry+F8（减少候选）
          └─ SelectIncreaseCandidate(+122B320) → entry+B0（增加候选）
       └─ TryAdjustStateTrade(+11FD470)
          ├─ Refresh(+11FBDA0) 重新刷新 entry+F8
          └─ Refresh(+11FBDA0) 重新刷新 entry+B0
```

`+131C2B0` 在仍有成功调整时会进入下一轮；每一轮都会重新执行候选准备，因此候选不是整个更新批次内固定不变的。

## 二、候选准备函数 `+131D540`

本文中的 `PrepareCandidates`、`PrepareCandidatesWorker` 都是分析阶段的语义化名称，均指向 `+131D540`；它们不是二进制中的原始符号。该工作体由 `+1326280` 在 `+1326405` 直接调用，`+131D170` 再调用 `+1326280`。

```cpp
// 功能：为一个州的贸易调整条目准备减少候选和增加候选。
// 入参：shared 为本轮共享上下文；entry 为州贸易调整条目。
// 返回值：写回 entry 的两个候选结构；返回值暂无独立业务含义。
function PrepareCandidates(shared, entry):
    grouped = shared.lookup(entry.field0C)
    context = BuildTradeContext(entry, grouped, shared.tables)
    state = ResolveState(entry.stateRef)
    randomState = MakeStateSeed(shared.seed, state.id)

    // 从州当前已有贸易中选择一个适合释放容量的商品。
    entry.remove = SelectReductionCandidate(
        state,
        context,
        false,              // 不绕过增加后的保护期
        randomState
    )                       // victoria3.exe+122AC50

    // 从全局商品库和两个方向中选择一个适合增加的商品。
    entry.add = SelectIncreaseCandidate(
        state,
        context,
        randomState
    )                       // victoria3.exe+122B320

    return
```

反汇编中，减少结果写入条目偏移 `+F8`，增加结果写入条目偏移 `+B0`。这两个槽位不是“出口”和“进口”两个固定槽位；每个候选自身还携带方向字段，方向 0/1 分别对应进口/出口是当前高可信解释。

## 三、减少候选 `+122AC50`

### 3.1 伪代码
```cpp
// 功能：从州已有贸易中选择调整后评分最低的减少候选。
// 入参：state 为州对象；context 为共享贸易计算上下文；
//       bypassProtection 表示是否绕过增加后的保护期；rng 为随机状态。
// 返回值：最低评分候选；没有合格商品时返回无效候选。
function SelectReductionCandidate(state, context, bypassProtection, rng):
    best = InvalidCandidate()

    for goods in state.list1DD8:
        signedUnits = ReadGoodsValue(state.table1D88, goods) / 100000
        if integer(signedUnits) == 0:
            continue

        // 最近增加过的商品在保护期内通常不能立即减少。
        if not bypassProtection:
            if GameTime() < LastTradeIncrease(goods) + 8 * 168:
                continue

        candidate = MakeCandidate(
            state,
            goods,
            direction = (signedUnits > 0 ? 1 : 0),
            mode = REDUCTION
        )

        // 这里刷新的是枚举过程中的临时候选，不是最终 entry.remove。
        Refresh(candidate, context)       // victoria3.exe+11FBDA0
        ApplySelectionRandomness(candidate, rng)

        if IsInvalid(best) or candidate.score < best.score:
            best = candidate
        else if candidate.score == best.score:
            best = RandomTieBreak(best, candidate, rng)

    return best
```

该函数的候选来源是 `state.list1DD8` 中当前已有贸易商品，而不是全局商品数据库。`table1D88` 的有符号容量值用于判断该商品是否存在贸易以及推导其方向。保护期判断中的 `8 * 168` 是商品增加后的减少保护条件，不能据此推断 `Refresh` 的调用周期。


### 3.2 保护期的 8*168 具体对应游戏中多久时间

这里对应 **8 个游戏周，也就是 56 个游戏日**，不是一周。

计算方式是：`168 = 7 × 24`（一周的小时数），所以 `8 × 168 = 1344` 小时。

游戏配置也直接确认了这一点：[00_ai.txt 第 1105 行](<D:/Games/Victoria3/Victoria 3/game/common/defines/00_ai.txt:1105>)：
```text
AUTONOMOUS_TRADE_WEEKS_BEFORE_TRADE_REDUCTION = 8
```

因此这条判断的意思是：**某商品的贸易量增加后，若尚未过去 8 周，就跳过该商品的减少候选**（前提是没有启用 `bypassProtection`）。这是减少贸易量的保护期，不能用它判断贸易更新函数多久执行一次。


### 3.3 ReadGoodsValue 读取的是什么值

**这里读取的是“该州分配给该商品的带方向贸易容量”，不是货物总价值、总利润，也不是 `价格 ×（生产订单量 − 消费订单量）`。** `ReadGoodsValue` 中的 `Value` 只是“表项数值”，这个临时命名容易让人误解为货币价值。

实际出现位置在[州贸易调整函数的候选准备函数.md](/D:/cebuild/ce-custom/Docs/2026-10-3-process1/important_notes/州贸易调整函数的候选准备函数.md:67)：

```cpp
signedUnits = ReadGoodsValue(state.table1D88, goods) / 100000
```

其含义是：

- `state.table1D88`：按商品索引的有符号贸易容量分配表。
- `/ 100000`：把定点整数转换成容量单位。
- **绝对值**：该商品占用的贸易容量单位数。
- **正负号**：贸易方向；当前分析对应正值出口、负值进口，方向名称仍保留文档中的验证边界。

关键证据来自实际写入：[反汇编 `+11FD91D～+11FD93B`](/D:/cebuild/ce-custom/Output/2026-10-3-process1/goal3_static_20261002/function_7FF777CED470.md:274) 显示，每成功增加一次贸易，向这张表加的是固定的 **`+100000` 或 `−100000`**；随后才向另外的表写入实际商品交易量。这说明容量和货物数量是分别记录的。

例如，表项为 `+300000`，这里得到 `signedUnits = 3`，表示该商品在正方向分配了 **3 单位贸易容量**，并不表示 3 件商品或 £3。减少候选函数用它判断该商品有没有现存贸易、属于哪个方向；至于是否值得减少，则由后面的 `Refresh` 计算评分。


### 3.4 MakeCandidate 伪代码

这里的 `MakeCandidate` 是分析用的语义化名称，不对应 victoria3.exe 中的独立函数。`+122AC50` 和 `+122B320` 都是在自己的栈帧中直接构造一个约 `0x48` 字节的临时候选结构，然后调用 `Refresh(+11FBDA0)`。

完整业务输入为 **州、商品、方向、评估模式**。原来的 `MakeCandidate(goods, direction, mode)` 省略了来自外层的州参数；应补成 `MakeCandidate(state, goods, direction, mode)`。以下 `stack_storage`、`load_u32` 是伪代码记法，不是游戏函数。

```cpp
// 功能：抽象两个选择函数内联的候选初始化，不包含 Refresh。
// 入参：state 为州对象；goods 为商品对象；direction 为方向字节（0/1）；
//       mode 为评估模式（0=减少，1=增加）。
// 返回值：约 0x48 字节的候选布局视图；数值计算字段初始均为零。
// 地址：减少路径 victoria3.exe+122AE7A..+122AEB5；
//       增加路径 victoria3.exe+122B501..+122B534；无独立函数入口。
function MakeCandidate(state, goods, direction, mode):
    candidate = stack_storage(0x48)
    candidate.goods       = goods                    // +00，8 字节商品指针
    candidate.direction   = direction                // +08，1 字节方向
    candidate.baseRevenue = 0                        // +10，8 字节基础收益
    candidate.unitRevenue = 0                        // +18，8 字节单位净收益
    candidate.score       = 0                        // +20，8 字节最终意愿评分
    candidate.stateRef    = load_u32(state + 0x08)    // +28，4 字节州引用
    candidate.mode        = mode                     // +2C，4 字节评估模式
    candidate.shortage    = 0                        // +30，8 字节短缺评分项
    candidate.quantity    = 0                        // +38，8 字节本次单位容量交易量
    candidate.advantage   = 0                        // +40，8 字节方向性贸易优势
    // +09..+0F 未见初始化，不把结构填充字节假定为已清零。
    return candidate
```

两条路径的使用方法如下。这里是调用点片段，不是新命名的游戏函数：

```cpp
// SelectReductionCandidate 内部：victoria3.exe+122AE7A..+122AEBB。
candidate = MakeCandidate(state, goods, signedUnits > 0 ? 1 : 0, 0)
Refresh(candidate, context) // victoria3.exe+11FBDA0，调用点 +122AEBB

// SelectIncreaseCandidate 内部：victoria3.exe+122B501..+122B53C。
candidate = MakeCandidate(state, goods, direction, 1)
Refresh(candidate, context) // victoria3.exe+11FBDA0，调用点 +122B53C
```

可以确认的业务含义如下：

- `state` 指定哪一个州在评估贸易：减少函数入口保存 `RCX → R14`，增加函数保存 `RCX → R13`，随后分别读取 `[r14+08]` 和 `[r13+08]`，写入候选 `+28`。`Refresh` 在 `+11FBDBD` 将候选地址加 `0x28`，通过 `+7C96A0` 解析州。州的生产方式数量修正、贸易优势及市场关联数据由后续刷新使用。
- `goods` 是商品对象指针；候选选择函数随后按该商品计算交易数量、贸易优势和评分。
- `direction` 是贸易方向字段。减少侧由带符号容量表的正负号生成；增加侧枚举 `0`、`1` 两个方向。现有运行时证据支持 `0=进口、1=出口`，但方向名称仍应视为高可信映射。
- `mode=0` 表示减少评估，`mode=1` 表示增加评估，独立于进口/出口方向。减少侧 `+122AEA1` 写零，增加侧 `+122B52D` 写一；短缺计算 `+11FBB5B` 比较候选 `+2C`，减少模式会减去本次数量；收益计算中增加模式复制贸易表并加入本次数量，减少模式使用原上下文。不能把两种评估都简化为同一套供给加减公式。
- 候选创建阶段不会写入贸易账本，也不会实际改变容量；它只构造临时结构，后续由 `Refresh` 填充 `quantity`、`advantage` 和评分字段。
- `candidate+28` 是候选的州引用字段。减少侧指令为 `mov eax,[r14+08]`，增加侧为同样从当前州对象读取并写入候选；`Refresh` 随后通过该字段解析州。它不是商品数量或评分。

不能把 `MakeCandidate` 解释成“按评分差计算数量”的函数。实际交易数量由 `Refresh` 内部的 `CalculateQuantityPerCapacity(+122AB50)` 计算，候选初始化只提供商品、方向、模式和若干初始字段。

对应反汇编：[减少选择函数](../../../Output/2026-10-3-process1/goal3_static_20261002/function_7FF777D1AC50.md)、[增加选择函数](../../../Output/2026-10-3-process1/goal3_static_20261002/function_7FF777D1B320.md)、[Refresh](../../../Output/2026-10-3-process1/goal3_static_20261002/function_7FF777CEBDA0.md)。

规范伪代码来源：[FakeCode 中的 MakeCandidate](../../../FakeCode/2026-10-3-process1/trade_candidate_functions.md#makecandidate内联候选初始化)。这里只恢复了上述两条路径的构造字段及其使用关系，没有认定游戏中存在通用构造 ABI。方向的 UI 名称保留验证边界；填充字节不属于已恢复的业务字段。

调用关系的关键证据在批处理函数 `+1326280`：串行分支的 `+1326405` 有一条直接 `call victoria3.exe+131D540`。而 `UpdateStateTrades(+131C2B0)` 在 `+131D170` 调用 `+1326280`。因此完整链路是：

```text
UpdateStateTrades(+131C2B0)
    └─ +131D170
       └─ +1326280（批处理/并行调度）
          └─ +131D540（串行工作体）
```

在 `+1326280` 的其他分支中，工作体可能通过任务/回调机制间接执行，所以静态调用图未必在每条路径都显示 `+131D540` 的直接 `call`。搜索时应使用 `+131D540`、`7FF777E0D540` 或对应反汇编文件名，而不是搜索 `PrepareCandidatesWorker`。

规范伪代码保存在 [FakeCode](../../../FakeCode/2026-10-3-process1/trade_candidate_functions.md#makecandidate内联候选初始化)。原先简写省略了州参数，完整输入为 `state, goods, direction, mode`；`candidate+28` 是从 `state+08` 复制的州引用，`candidate+2C` 是评估模式（0=减少、1=增加）。


## 四、增加候选 `+122B320`

### 4.1 SelectIncreaseCandidate 伪代码
```cpp
// 功能：从允许交易的商品及两个方向中选择评分最高的增加候选。
// 入参：state 为州对象；context 为共享贸易计算上下文；rng 为随机状态。
// 返回值：最高评分候选；没有合格商品时返回无效候选。
function SelectIncreaseCandidate(state, context, rng):
    best = InvalidCandidate()

    for direction in [0, 1]:
        for goods in GoodsDatabase:
            if not PassCountryAndMarketFilters(goods, state):
                continue
            if not GoodsCanBeTraded(goods):
                continue
            if ExistingTradeHasOppositeDirection(state, goods, direction):
                continue

            candidate = MakeCandidate(
                state,
                goods,
                direction,
                mode = INCREASE
            )

            // 每个商品/方向组合都可能在此被刷新一次。
            Refresh(candidate, context)       // victoria3.exe+11FBDA0
            ApplySelectionRandomness(candidate, rng)

            if not MeetsIncreaseThreshold(candidate):
                continue
            if IsInvalid(best) or candidate.score > best.score:
                best = candidate
            else if candidate.score == best.score:
                best = RandomTieBreak(best, candidate, rng)

    return best
```

该函数会遍历商品库和两个方向，但最终只返回一个候选。因此 `entry.add` 不是分别保存一个进口商品和一个出口商品，而是两个方向所有合格组合中的最高评分者。

### 4.2 PassCountryAndMarketFilters 内部实现

`PassCountryAndMarketFilters(goods, state)` 不是二进制中的独立函数，而是对 `+122B320` 商品循环中几段内联判断的分析命名。它不读取 `Refresh` 使用的贸易计算 `context`，也不按价格、供需、贸易优势或最终评分筛选。

更准确的语义伪代码是：

```cpp
// 功能：概括增加候选中的国家商品资格过滤；不是独立 ABI 函数。
// 入参：goods 为商品对象；state 为州对象。
// 返回值：通过过滤为 true；否则为 false。
// 地址：victoria3.exe+122B37E..+122B3D7、+122B440..+122B495。
function PassCountryAndMarketFilters(goods, state):
    // Resolve(+7B0AB0) 解析国家，+7C0380 解析市场。
    if state.field_11B8 != 0 and state.ref_B48 != 0xFFFFFFFF:
        associated = call_address(+7C33B0, address_of(state.ref_B48))
        marketRef = associated.field_10
    else:
        owner = call_address(+7B0AB0, address_of(state.ref_E48))
        marketRef = owner.field_9D4
    market = call_address(+7C0380, address_of(marketRef))
    country = call_address(+7B0AB0, address_of(market.ref_848))

    // 数组属于国家对象；列表业务名称尚未由写入点确认。
    if state.field_11B8 == 0:
        for index in [0, country.count_2414):
            if country.goodsPointers_2408[index] == goods:
                return false

    // +C34A80 是真实调用；限制条目的具体业务类型仍需确认。
    return call_address(+C34A80, country, goods)
```

规范伪代码来源：[FakeCode](../../../FakeCode/2026-10-3-process1/trade_candidate_functions.md#passcountryandmarketfilters内联过滤)。`call_address` 表示调用给定 RVA 的原始函数，不是新增业务函数名。

这里的 `country` 是从州所属市场关系解析出的国家/市场所有者对象，不是 `SelectIncreaseCandidate` 的 `context`。`context` 在后面调用 `Refresh(candidate, context)` 时用于模拟贸易数量、价格、优势和收益。

具体证据如下。

1. **国家对象上的商品限制列表**

   `+122B320` 普通路径读取国家对象中的：

   - `country + 0x2408`：商品指针数组；
   - `country + 0x2414`：数组元素数量。

   循环逐项比较当前 `goods`。命中时跳过该候选。`state + 0x11B8 != 0` 时不执行这段列表比较。列表的“禁运商品列表/特殊市场限制列表”具体字段名尚未由写入点完全确认，因此文档不把它硬命名为“市场已有贸易列表”。

2. **国家商品谓词 `+C34A80`**

   调用约定为 `RCX=country`、`RDX=goods`。函数开头检查 `goods + 0x40` 的标志：

   - `bit1` 未设置时立即失败；
   - `bit0` 设置时立即失败。

   随后它遍历国家 `+3B0/+3BC` 的引用列表，解析对象、检查虚函数和状态字段，再遍历其子对象中的类型化条目。商品比较分支命中时最终返回 `false`；未命中时返回 `true`。这些对象的具体业务类型尚未确认，不能直接等同于国家禁运列表。`add_banned_goods` / `remove_banned_goods` 是游戏中存在的禁用商品机制，但尚未证明它们对应此函数的条目。

3. **通过后的后续检查**

   `+122B49B..+122B4FB` 检查商品 ID 和州贸易表的存在位，并比较已有带符号容量的方向；非零且方向相反时跳过候选。这里的相反方向检查是内联代码，不是调用 `+122AAD0`。之后才构造候选并调用 `Refresh(+11FBDA0)`。

指令来源：[增加候选反汇编](../../../Output/2026-10-3-process1/goal3_static_20261002/function_7FF777D1B320.md)。`+C34A80` 的内部说明来自本地游戏可执行文件的静态反汇编；其类型化条目和间接调用尚未全部恢复。

因此，“通过 filter”只表示：

> 这个 `goods,state` 组合在国家商品限制、商品类型和特殊市场路径层面具备成为候选的资格。

它并不表示该商品一定值得进口/出口，也不表示最终会被选中。最终是否成为 `entry+B0` 的增加候选，还要经过相反方向贸易检查、`Refresh` 计算以及评分门槛和随机并列处理。


## 五、候选选择与最终执行的关系

候选选择阶段和 `TryAdjustStateTrade` 阶段都可能调用 `Refresh`，但作用不同：

1. `+122AC50`、`+122B320` 在枚举过程中刷新许多临时候选，用于比较并选出最低/最高评分者。
2. 选择结果写入 `entry+F8` 和 `entry+B0`。
3. `+11FD470` 开始时再次刷新最终的 `e.remove` 和 `e.add`，确保评分、数量、优势等字段基于当前上下文。
4. 后续逻辑决定是否实际移除或增加一单位贸易容量；`Refresh` 本身不写入贸易账本。
