## 判定流程

该函数并不是给商品设置一个布尔型的“短缺”状态，而是为候选写入一个短缺评分指标 `c+30`。只有以下条件全部满足时，该指标才可能大于零：

1. **方向为 0**：反汇编只在 `c+08 == 0` 时继续执行。现有数据支持方向 0 大致对应进口，但这里保留方向编号，不把尚未独立确认的枚举名称写死。
这个基本可以确认为进口，因为只有进口才需要计算短缺。

2. **商品通过市场资格检查**：函数会解析候选的市场/商品信息，检查商品索引有效、对应商品位已设置，并检查市场商品表对应项大于零。该表的正式业务名称尚未确认，因此伪代码统一称为 `HasEligibleMarketGoods`。
3. **需求大于零**：需求读取函数 `+11FCF70` 返回的值必须大于零；需求小于等于零时，`c+30 = 0`。
4. **有效供给低于需求的一半**：有效供给由 `+11FD0D0` 读取；减少模式还要减去本次候选数量 `c+38`。如果供给小于等于零，直接取最大值 `0.5`。

因此，正供给时只有当 `supply / demand < 0.5`，短缺指标才为正；供给恰好为需求的 50% 时指标为 0，而不是正值。

## 短缺曲线

令 `ratio = supply / demand`，其中 `ratio` 是 100000 倍定点数。实际计算等价于：

```text
shortage = clamp(1 - ratio / 0.5, 0, 0.5)
```

对应的定点伪代码必须写成：

```cpp
shortage = Clamp(100000 - DivideFixedPoint(ratio, 50000), 0, 50000);
```

这里的 `100000` 是短缺评分的单位 1.0，`50000` 同时表示阈值 0.5 和最大短缺值 0.5。不能把第一个 `100000` 写成 `50000`；否则会错误地把公式理解为供需比低于 25% 才开始产生短缺。

例如需求为 100 时：

| 有效供给 | 供需比 | `shortage` | 后续评分增加量 |
|---:|---:|---:|---:|
| 60 | 0.60 | 0 | 0 |
| 50 | 0.50 | 0 | 0 |
| 40 | 0.40 | 0.20 | 60 |
| 25 | 0.25 | 0.50 | 150 |
| 0 或更低 | 不适用 | 0.50 | 150 |

后续 `+11FC320` 将该指标乘以 300 加入最终意愿评分。因此这里的“短缺”是贸易候选评分中的一项奖励：它表示该候选对应的有效供给不足，而不是直接修改商品的全局短缺状态。

## 增加与减少模式的差异

- **增加模式 `mode == 1`**：短缺计算使用读取到的当前供给 `supply`，不会像收益模拟那样先把本次数量加入供给。因此，即使增加该候选后供给会改善，短缺评分仍基于增加前的供给。
- **减少模式 `mode == 0`**：先计算 `supply - c->quantity`，再进行短缺判断。因此移除该候选后会导致供给跌到需求一半以下时，该候选会获得更高的保留意愿评分。
- **方向 1**：不执行上述供需计算，直接将 `c+30` 清零。

        simulated, c->goods, c->direction, priceDifference);

**简单说：`UpdateCandidateRevenue` 用来估算“这一份贸易量值多少钱”，供后续候选评分使用。** 它只做模拟和收益计算，不真正执行进出口调整。见 `Docs/important_notes/刷新候选函数.md:98`。

### 算法流程
1. **取得本次调整量 `q = c.quantity`**：这是调整一单位贸易容量对应的商品量，不是该商品最多可交易的总量。
2. **准备计算环境**：
   - **增加模式 `mode == 1`**：复制相关商品表，把 `q` 加入对应方向的两张表，模拟**增加贸易后的市场状态**。
   - **减少模式 `mode == 0`**：直接按当前上下文计算；这里**没有先减去 `q`**。
3. **计算单位净收益 `p`**：先计算对应方向的价差，再交给净收益计算函数处理。
4. **写回两个结果**：
   - `c+0x18`：单位净收益 `p`。
   - `c+0x10`：本次调整量的基础收益 **`R = q × p`**。内部使用定点数，原始整数相乘后需除以 `100000`。

### 如何理解
- **增加候选**问的是：“新增这批货以后，按新状态计算，这批货能贡献多少收益？”
- **减少候选**问的是：“按当前状态，这批现有贸易量贡献多少收益？”——不是直接计算减少后的收益变化，也不是自动把收益取负。

例如 `q = 10`，增加后的单位净收益 `p = 2`，则基础收益为 `20`；之后由 `CalculateDesirability` 结合其他因素生成最终评分。

**注意：这份伪代码没有展开价差和单位净收益的内部公式，因此目前能明确的是上述流程，不能仅凭这里断言 `p` 具体扣除了哪些成本。**

// 功能：检查候选数量限制，并合成最终意愿评分。
// 入参：候选 c、共享计算上下文 context；返回：无业务返回值，最终评分写入 c+20。
// 说明：评分采用 100000 倍定点数；数量限制失败时写入 INT64_MIN。
void CalculateDesirability(Candidate* c, TradeContext* context)
{
    int64 worldOpposite = ReadWorldOppositeTrade(c, context);
    int64 marketOpposite = ReadMarketOppositeTrade(c, context);
    int64 localDirection = ReadMarketDirectionTrade(c, context);

    // 本市场方向量超过外部反方向可承接量的两倍时，候选直接无效。
    if (localDirection > MultiplyFixedPoint(worldOpposite - marketOpposite, 200000)) {
        c->desirability = INT64_MIN;
        return;
    }

    int64 score = c->baseRevenue;                         // c+10
    int64 tariff = ReadEffectiveTariff(c, context);
    if (tariff > 0)
        score -= MultiplyFixedPoint(tariff, 2500000);     // tariff × 25

    int64 subsidyDelta =
        MultiplyFixedPoint(ReadSubsidy(c, context), 10000000)
        - MultiplyFixedPoint(ReadOppositeSubsidy(c, context), 10000000);

    // 方向 0 且供给不足时，正的补助差额放大 20 倍。
    if (subsidyDelta > 0 && c->direction == 0 && IsLowSupplyForCandidate(c, context))
        subsidyDelta = MultiplyFixedPoint(subsidyDelta, 2000000);
    score += subsidyDelta;

    if (worldOpposite > 0)
        score -= MultiplyFixedPoint(
            DivideFixedPoint(marketOpposite, worldOpposite), 100000000);

    score += MultiplyFixedPoint(c->shortage, 30000000);   // shortage × 300
    c->desirability = score;                              // c+20
}
