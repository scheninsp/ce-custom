## TryAdjustStateTrade 的一些部分的解释

### goods.flags40 的解释
flags40：
  bit0 (0x1)：高度疑似“本地商品/禁止普通市场贸易”标志；
  bit1 (0x2)：高度疑似“可参与市场贸易”标志。

这与游戏中的商品分类很吻合：服务、电力等本地商品通常只在州内或市场内部处理，不能像木材、艺术品那样建立普通进出口贸易。

### L28-37 代码解释
L28-37 这段代码是在判断“要不要撤掉州里现有的一单位贸易”。

先确认确实有可撤除的商品，然后设定一个最低保留分数：正常运行时是 `25fp`；游戏正在初始化时，标准降低为 `18.75fp`（25 的 75%）。

e.xxx.score 就是 CalculateDesirability 计算出来的评分。

接着检查是否已经达到贸易容量上限，并且新增候选商品与当前商品不同、评分还明显更高（新增评分超过当前评分的两倍）。

满足这个“更好的替代品”条件，或者当前贸易评分已经低于最低保留分数时，就调用 `RemoveOneTradeUnit` 撤掉一单位旧贸易，并记下本轮已经发生了撤除。

这样做的目的，是在容量已满时给更有价值的商品让位，同时清理评分过低的旧贸易；初始化阶段则会稍微宽松一些，避免过早撤除。

### e.remove.goods 和 e.add.goods 
e.remove.goods 和 e.add.goods 不是“包含所有货物的列表”，而是两个单个候选结构中的 goods 指针/引用字段。Refresh(+11FBDA0) 也不会向其中追加货物，它只根据候选中已经选定的商品、方向和上下文，重新计算数量、优势、评分等字段。

| 字段 | 候选来源 |
|---|---|
| `e.remove.goods` | 当前州已有贸易集合 `state+0x1DD8` 中筛选出的一个商品 |
| `e.add.goods` | 全局商品数据库中通过过滤的一个商品，并配合一个方向 |
| 候选其余字段 | 先清零/设为无效值，再由 `Refresh` 计算 |

可以确认的结论是：
1. e.remove 和 e.add 各自最多代表一个候选商品，不是完整商品列表。
2. e.remove 初始候选来自州已有贸易。
3. e.add 初始候选来自商品数据库筛选。
4. 候选结构开始时确实是空/无效状态，随后由候选选择函数写入一个商品。
5. Refresh 负责刷新候选数据，不负责枚举或追加本轮所有增减商品。

调用约定是：

```text
RCX = table       商品数值表
RDX = goods       商品对象
R8  = delta       定点数增量
```

其核心逻辑可还原为：

```cpp
AddByGoods(table, goods, delta):
    if delta == 0:
        return

    index = goods + 0x10
    if not ValidGoodsIndex(index):   // 调用 +1026630
        return

    oldValue = table[index]          // 无效位时视为 0
    newValue = oldValue + delta

    table[index] = newValue

    if newValue == 0 and table.flags48 == 0:
        清除该商品的存在位
        释放或整理存储
    else:
        确保该商品存在位已设置
        必要时分配存储
```

其中：

- `goods+0x10` 是商品索引；
- `table+0x20` 是按商品索引分组的存在位图；
- `table+0x08` 指向实际数值存储；
- `+1026700` 和 `+1026970` 分别处理存在位/存储结构的维护。

之所以连续调用五次，是因为这不是重复写同一个表，而是更新五个不同的统计表：

```text
1. state.table1D88
   增加或减少该商品的容量方向值：
   direction == 1 ? +1fp : -1fp

2. selectedDirectionTable
   增加该商品的贸易数量

3. selectedMarketTable
   增加该商品的市场统计数量

4. selectedGlobalTable
   增加该商品的全局统计数量

5. selectedValueTable
   增加 quantity * advantage，用于价值/评分统计
```

因此一次贸易容量被接受后，需要同时更新“容量方向、数量、市场数量、全局数量、加权价值”五套账本。后续容量计算、市场汇总和贸易评分分别读取这些表，所以必须分别调用 `AddByGoods`。


# RemoveOneTradeUnit（+11FAF20）
```cpp
// 功能：删除一个贸易容量单位及对应的数量贡献。
// 入参：商品、方向、单位数量、系数和五个数值表；返回：无业务返回值。
function RemoveOneTradeUnit(goods, direction, quantity, coefficient, tables):
    if not valid(goods): return
    SubtractByGoods(tables.capacity, goods, direction == 1 ? 1fp : -1fp)
    SubtractByGoods(tables.direction, goods, quantity)
    SubtractByGoods(tables.market, goods, quantity)
    SubtractByGoods(tables.global, goods, quantity)
    SubtractByGoods(tables.value, goods, MulFixed(quantity, coefficient))
```
