### 完整低层伪代码

以下使用 C 风格伪代码表达指令语义，不是可直接编译的原始 C++。辅助记号：`I64(x)` 表示取整数低 64 位后按有符号补码解释，`U64(x)` 表示取低 64 位后按无符号解释；`signed128(x)` 表示有符号 128 位扩展；`arithmetic_shift_right` 为算术右移。这样显式保留机器整数回绕，避免把 C/C++ 有符号溢出误写成有定义的普通运算。

```cpp
const int64 SCALE = 100000;                  // 0x186A0，定点比例
const int64 LIMIT = 3037000499;              // 0xB504F333
const uint64 DOUBLE_LIMIT = 6074000998;      // 0x16A09E666
const int64 DIV_MAGIC = 0x29F16B11C6D1E109;

// 功能：还原有符号定点除法的乘高位、移位和负数修正序列。
// 入参：有符号 64 位整数 x；返回：x / 100000，向零截断。
int64 DivideByScale(int64 x)
{
    // 对应单操作数 imul：完整有符号乘积的高 64 位写入 RDX。
    int64 high = I64(arithmetic_shift_right(signed128(x) * DIV_MAGIC, 64));
    int64 q = arithmetic_shift_right(high, 14);  // sar ...,0E
    return q + (q < 0 ? 1 : 0);                // shr ...,3F 后相加
}

// 功能：还原本函数内联的两分支定点乘法。
// 入参：原始定点整数 a、b；返回：缩放后的原始定点整数，保留机器溢出语义。
int64 MultiplyFixedRaw(int64 a, int64 b)
{
    // 对应 +122AB99..+122ABA9 的无符号比较；两项都通过才走快路径。
    bool aFits = U64(signed128(a) + LIMIT) <= DOUBLE_LIMIT;
    bool bFits = U64(signed128(b) + LIMIT) <= DOUBLE_LIMIT;

    if (aFits && bFits) {
        // +122ABAB..+122ABC7：先乘，再除以 100000。
        // 此分支范围保证 a*b 不超出有符号 64 位整数。
        int64 product = I64(signed128(a) * b);
        return DivideByScale(product);
    }

    // +122ABCC..+122ABE0：按有符号数值比较，不是比较绝对值。
    int64 hi = (b < a) ? a : b;              // R8 = max(a,b)
    int64 lo = (b > a) ? a : b;              // R9 = min(a,b)

    // +122ABE4..+122AC06：把较大的操作数拆成整数商和余数。
    int64 quotient = DivideByScale(hi);
    int64 scaledQuotient = I64(signed128(quotient) * SCALE);
    int64 wholePart = I64(signed128(quotient) * lo);
    int64 remainder = I64(signed128(hi) - scaledQuotient);

    // +122AC09..+122AC21：只对余数乘积做缩放，再加整数部分。
    int64 remainderProduct = I64(signed128(remainder) * lo);
    int64 fractionalPart = DivideByScale(remainderProduct);
    return I64(signed128(wholePart) + fractionalPart);
}

// 功能：计算指定州与商品的单位交易数量，并施加最小交易量下限。
// 入参：state 为州对象，outQuantity 为 8 字节结果位置，goods 为商品对象。
// 返回：原始 outQuantity 指针；*outQuantity 接收数量的原始定点整数。
int64* CalculateQuantityPerCapacity(byte* state, int64* outQuantity, byte* goods)
{
    // +122AB5A..+122AB75：先取州关联对象，再读取商品基础量及选择值。
    byte* modifierOwner = ReadPointer(state + 0x18B0);
    int64 baseRaw = ReadInt64(goods + 0x50);
    int64 modifierRaw;
    uint16 selector = ReadUInt16(moduleBase + 0x50D6FB0);

    // +122AB79：真实调用目标 +844150；这里的函数名仅描述数据流。
    ReadModifier_844150(modifierOwner + 0x10, &modifierRaw, uint32(selector));

    // +122AB7E..+122AC21：结果来自输出槽；没有使用上述调用的 RAX。

    int64 quantityRaw = MultiplyFixedRaw(baseRaw, factorRaw);

    // +122AC24..+122AC37：有符号比较，选择数量与下限中的较大者。
    int64 minimumRaw = ReadInt64(moduleBase + 0x5889E28);

    // +122AC3A..+122AC42：返回输出指针。
```

### 两个乘法分支为什么存在

快路径的条件等价于两个操作数都位于 `[-3037000499, +3037000499]`。该阈值是 `floor(sqrt(INT64_MAX))`，平方为 `9223372030926249001`，因此两数可以先做有符号 64 位乘法，再向零截断除以 `100000`。两次 `ja` 都是**无符号**跳转，不能直接把汇编里加上偏移量后的范围比较译成普通有符号比较。

慢路径把有符号数值较大的操作数拆为 `hi = quotient*100000 + remainder`，计算：

```text
quantityRaw = quotient * lo + trunc_toward_zero(remainder * lo / 100000)
```

在中间乘法和加法均不溢出的情况下，这与 `trunc_toward_zero(a*b/100000)` 等价，可减少直接乘积过大的问题。但汇编**没有饱和处理，也没有检查溢出标志**；`quotient*lo`、`remainder*lo` 和最终加法仍是 64 位运算。因此不能声称慢路径对任意两个 64 位整数都不会溢出。上面的低层伪代码保留了这些回绕行为。

`0x29F16B11C6D1E109` 是这里用于除以 `100000` 的乘法常量；配合乘积高位、算术右移 14 位和负数加一，结果向零截断，不是浮点除法，也不是四舍五入。对负数尤其不能替换为向负无穷取整。

### 与刷新候选函数的衔接

[调用点证据](../../Output/goal3_static_20261002/function_7FF777CEBDA0.md) 的 `+11FBDC9..+11FBDDF` 表明，调用者把 `[candidate+0x00]` 作为商品指针，传入栈上的临时输出槽，再通过返回指针取值并写入 `candidate+0x38`：

```cpp
// 功能：说明刷新候选时数量字段的实际写回过程，仅展示相关片段。
// 入参：candidate 为候选对象，resolvedState 为已解析的州指针；返回：无。
void RefreshQuantityFragment(byte* candidate, byte* resolvedState)
{
    int64 temporaryQuantity;
    byte* goods = ReadPointer(candidate + 0x00);
    int64* result = CalculateQuantityPerCapacity(resolvedState, &temporaryQuantity, goods);
    WriteInt64(candidate + 0x38, *result);
}
```

因此，文档开头的 `c.quantity = CalculateQuantityPerCapacity(state, c.goods)` 是省略输出参数后的业务写法。真实 ABI 返回的是指针；它本身也没有接收候选的方向参数、当前容量、评分或贸易优势，不能据此函数单独推导最终容量份额。
