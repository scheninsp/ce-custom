# 刷新候选函数评分影响因子—断点选择建议 1

日期：2026-10-02

## 结论

如果下一步允许让游戏继续运行，**首选断点是**：

```text
victoria3.exe+11FD5C9
```

也就是当前已经命中的代码断点。它位于执行一次候选调整的前置路径中，并且当前 `R14+0x1D58`、`R14+0x1D5C` 两个字段刚刚被读取；继续运行后重新命中它，可以再次取得同类候选现场，不需要换到一个更靠后的、可能已经脱离评分计算的地址。

如果要采集评分合成结果，推荐新增或临时使用的**第二优先级代码断点**是：

```text
victoria3.exe+11FC320
```

这是 `Refresh` 尾部跳转进入的评分/数量限制合成入口。它比 `+11FD5C9` 更接近最终 `D`，但它可能被多个候选路径或调用场景复用，命中后必须用寄存器和候选指针确认当前是否仍是目标贸易候选。

如果只希望观察一次完整执行，不想在中途分析太多，建议保留当前断点作为入口，不要直接把唯一断点换到 `+11FC320`。

## 一、地址选择依据

### 1. `+11FD5C9`：当前最稳妥的复现断点

当前现场：

```text
RIP = victoria3.exe+11FD5C9
R14 = 3A484D9DB60
RSP = 8C5DE8D870
```

相邻指令为：

```text
+11FD5BB  mov eax,[r14+00001D5C]
+11FD5C2  mov [rsp+00000330],eax
+11FD5C9  mov eax,[r14+00001D58]
+11FD5D0  mov [rsp+50],eax
```

该位置的优势：

- 已证明属于当前候选调整调用 `+11FD470` 的中间路径。
- 可同时取得 `R14`、候选对象 `RDI`、方向相关的当前寄存器和临时栈上下文。
- 不需要猜测 `+11FC320` 命中的其他调用场景。
- 当前两个数据断点正好对应 `R14+0x1D58` 和 `R14+0x1D5C`，便于核对字段值。

缺点是它位于最终评分合成之前；如果只在此处停止，不能直接看到最终写入 `candidate+0x20` 的 `D`。

### 2. `+11FC320`：最终评分路径断点

静态反汇编确认：

```text
+11FC077  jmp +11FC320
+11FC320  push rbp
```

`+11FC320` 是 Refresh 尾部的评分/数量限制合成入口。它适合观察：

- 数量限制判断；
- 世界、市场和本地方向数量的读取；
- 评分中间值的定点乘法；
- 最终候选评分字段的写入路径。

但它不一定只服务于用户当前这一种候选。命中时要记录：

```text
RDI/R14/RCX/RDX
候选对象可能的 +0x00、+0x08、+0x20、+0x30、+0x38、+0x40
当前 direction
当前 goods/state 指针
```

不能只因为 RIP 是 `+11FC320`，就直接把这次命中当成目标候选评分。

### 3. `+11FD470`：候选调整执行入口

`+11FD470` 是执行一次调整的入口，调用者 `+131D219` 位于上层反复调整循环中：

```text
+131D219  call +11FD470
+131D21E  or r12b,al
```

它适合观察一次完整“减少、替换、增加、成功计数”的决策，但入口处还没有完成本次刷新；如果目的是收集价格、补助、关税和评分输入，当前 `+11FD5C9` 以及 `+11FC320` 更有价值。

## 二、推荐操作方案

### 方案 A：最安全，继续使用当前断点

1. 保存当前现场快照：RIP、RSP、R14、RDI、RSI、断点列表、目标 PID。
2. 保持 `victoria3.exe+11FD5C9` 不变。
3. 仅继续运行到该断点再次命中。
4. 命中后立即读取寄存器、断点列表和候选相关内存。
5. 通过 `R14+0x1D58`、`R14+0x1D5C` 是否可读，以及 `RDI` 相关候选字段，判断是否为同类评分路径。
6. 确认是目标候选后，再考虑短距离运行到 `+11FC320`；不要在未确认对象的情况下直接采集。

此方案最不容易脱离当前贸易容量和评分上下文，因为断点位置没有改变，且已经确认它位于当前路径中。

### 方案 B：保留入口断点，增加评分尾部断点

推荐同时保留：

```text
victoria3.exe+11FD5C9
victoria3.exe+11FC320
```

一次继续运行可能先命中其中一个。处理规则：

- 先命中 `+11FD5C9`：记录当前候选快照，确认后继续运行。
- 后续命中 `+11FC320`：记录最终评分路径现场，并比较候选对象、商品、方向和数量字段。
- 如果 `+11FC320` 先命中，先只读确认其 `RCX/RDX` 是否能关联到当前 `+11FD470` 的候选；不能关联时不要把结果写入分析结论。

此方案需要增加断点，属于有副作用的调试操作；在实际执行前应先由用户确认。

### 方案 C：只断最终字段写入附近

不推荐把唯一断点直接换到最终 `candidate+0x20` 的写入指令，原因是：

- 最终写入前可能已经丢失 `R14`、临时上下文和候选选择来源；
- 同一写入形式可能被多个分支复用；
- 命中后不容易确认对应的是增加候选、减少候选还是其他评分对象。

如果必须观察写入，应该同时保留 `+11FD5C9` 或 `+11FC320` 作为上游识别点。

## 三、如何避免断点脱离当前贸易候选

### 1. 不使用“只看地址”的判断

每次命中都必须记录以下身份信息：

```text
目标进程 PID
模块基址
RIP
RSP
RDI
RSI
R14
RCX
RDX
当前 direction
候选字段 +0x00、+0x08、+0x10、+0x18、+0x20、+0x30、+0x38、+0x40
```

地址相同只能说明命中了同一段机器码，不能证明是同一个州、商品或候选。

### 2. 使用候选身份指纹

第一次命中当前断点时，保存：

```text
candidate_ptr = RDI 或调用约定中确认的候选指针
state_ptr     = 候选对象中解析出的州/市场对象
 goods_ptr    = 候选 + 0x00 或后续确认的商品指针
 direction    = 候选 + 0x08
 q            = candidate + 0x38
 p            = candidate + 0x18
 R            = candidate + 0x10
 D            = candidate + 0x20
 H            = candidate + 0x30
 advantage   = candidate + 0x40
```

其中 `RDI`、字段偏移和方向含义必须以该次调用的寄存器/内存现场核对；如果一次命中无法验证，不要强行套用。

后续命中只有同时满足下列条件，才可视为同一分析链：

- 仍是 `victoria3.exe` PID `43884`；
- 模块基址没有变化；
- `RDI/R14` 对象仍可读；
- 商品指针、方向和候选字段结构可读；
- `q`、`p`、`R`、`D` 字段的变化符合当前调用场景；
- 断点前后的暂停状态没有变化。

### 3. 用调用者确认方向

`+131D219` 会调用 `+11FD470`，且上层循环会重复调用：

```text
+131D219  call +11FD470
+131D21E  or r12b,al
+131D221  进入下一个条目
+131D27F  根据本轮是否成功决定是否继续
```

因此同一个代码断点可能在多个州条目、多个商品和多个轮次中命中。不能把连续两次命中自动当成同一候选；必须比较候选指针和商品/方向字段。

### 4. 记录命中次数和停止原因

每次继续运行前后记录：

```text
run_id
命中地址
命中序号
命中前后 RIP/RSP
候选指针
商品指针
direction
q/p/R/D/H/advantage
```

如果命中后 `RSP`、`R14`、`RDI` 与前一轮完全不同，应视为新的候选实例，不能直接合并数值。

## 四、针对当前现场的具体建议

当前不要移动已有的：

```text
victoria3.exe+11FD5C9
```

第一次继续运行时，推荐只做：

1. 保持 `+11FD5C9` 不变并继续运行到该断点。
2. 立即采集只读寄存器和候选字段。
3. 如果 `R14+0x1D58`、`R14+0x1D5C` 仍然存在且 `RDI` 结构与当前现场一致，则记录为同一类贸易评分路径。
4. 只有在确认候选身份后，才继续到 `+11FC320`。
5. 第一次不要直接使用 `Run` 让游戏长时间运行；目标是从一个已知评分命中点到下一个已知评分命中点。

如果需要减少误命中，可先把 `+11FC320` 设为临时辅助断点，但必须同时保留 `+11FD5C9`，并在每个命中点做身份验证。

## 五、不能保证的事项

- `+11FD5C9` 可能在不同候选、不同州或不同更新轮次重复命中。
- `+11FC320` 可能被其他相似评分路径复用。
- 当前断点命中只能证明执行流经过该地址，不能证明候选一定属于用户正在观察的贸易条目。
- 如果游戏状态在继续运行期间发生贸易更新，候选对象指针和临时栈数据可能变化；必须以每次新命中的现场为准。

## 六、最终建议

推荐优先级：

1. **首选：`victoria3.exe+11FD5C9`**，作为已验证的候选评分前置断点。
2. **辅助：`victoria3.exe+11FC320`**，作为最终评分合成断点，但命中后必须验证候选身份。
3. **上游：`victoria3.exe+11FD470`**，用于确认一次调整调用的入口，不作为主要评分输入采集点。
4. **不推荐：只在最终字段写入点设置唯一断点**，因为容易丢失候选身份和输入上下文。

在实际继续运行之前，建议先保存当前断点列表和寄存器快照；如果用户确认继续执行，我可以按上述方案先保持 `+11FD5C9`，再设计一次最小步进采集流程。
