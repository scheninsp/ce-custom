其核心逻辑可还原为：

```cpp
AddByGoods(table, goods, delta):
    if delta == 0:
        return

    index = goods + 0x10
    if not ValidGoodsIndex(index):   // 调用 +1026630
        return

    oldValue = table[index]          // 无效位时视为 0
    newValue = oldValue + delta

    table[index] = newValue

    if newValue == 0 and table.flags48 == 0:
        清除该商品的存在位
        释放或整理存储
    else:
        确保该商品存在位已设置
        必要时分配存储
```

其中：

- `goods+0x10` 是商品索引；
- `table+0x20` 是按商品索引分组的存在位图；
- `table+0x08` 指向实际数值存储；
- `+1026700` 和 `+1026970` 分别处理存在位/存储结构的维护。

之所以连续调用五次，是因为这不是重复写同一个表，而是更新五个不同的统计表：

```text
1. state.table1D88
   增加或减少该商品的容量方向值：
   direction == 1 ? +1fp : -1fp

2. selectedDirectionTable
   增加该商品的贸易数量

3. selectedMarketTable
   增加该商品的市场统计数量

4. selectedGlobalTable
   增加该商品的全局统计数量

5. selectedValueTable
   增加 quantity * advantage，用于价值/评分统计
```

因此一次贸易容量被接受后，需要同时更新“容量方向、数量、市场数量、全局数量、加权价值”五套账本。后续容量计算、市场汇总和贸易评分分别读取这些表，所以必须分别调用 `AddByGoods`。
