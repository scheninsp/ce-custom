# 周期推算操作步骤指南

更新日期：2026-10-03（北京时间）。目标：观察指定州/贸易中心、指定商品在一个完整游戏周内发生多少次贸易增减，区分候选评估、调整提交、实际写入及净变化。

已增加 `Scripts/ce_trade_cycle.py` 自动编排入口。下方旧的手工步骤保留作为原理及故障排查参考；采用自动模式时，以本节分工和状态机为准，不再逐次人工 Run、记录或检查条件。

## 简化入口：由 agent 执行和检查

用户已在本次会话授权自动 CE Run；不授权改游戏内存、时间或速度。用户只需要：**必要时解除游戏自身暂停，在两个周边界告诉 agent 屏幕上的真实游戏日期**。不要与脚本同时点击 Run、Step、修改条件或运行另一个编排进程。

脚本自动完成：身份及调用指令核验、原生断点 Active/On Hit 核验、条件保存前比较与保存后读回、提交事件序号及精确数量记录、Run、等待、窗口统计和导出。现有诊断断点不删除：命中 `+11FD5C9` 且 `R14` 是已确认九州时，保存快照后继续；其他未知停点立即停止。

三个现有基础断点更新为本实验的原生 Complex 条件，不新增硬件槽，不替换 callback。两个提交条件仍筛选州表和木材，匹配后停下；agent 采集检查后才再次 Run。边界条件记录序号并停下；下一边界自动解除 armed，避免把下一批更新算进去。计数序号在 CE 侧生成，同一现场重复采集不重复计数。

所有命令均可在仓库根目录的 CMD/PowerShell 运行；通常由 agent 负责，不需要用户逐条输入：

| 阶段 | agent 命令 | 停下来等待什么 |
| --- | --- | --- |
| 只读核验 | `python Scripts/ce_trade_cycle.py inspect` | 检查失败时解释，不 Run |
| 合成条件测试 | `python Scripts/ce_trade_cycle.py selftest` | 六个局部模拟用例，不污染真实实验 |
| 安装实验 | `python Scripts/ce_trade_cycle.py prepare` | 自动比较旧条件、修改和读回，不 Run |
| 寻找完整起点 | `python Scripts/ce_trade_cycle.py seek --allow-run` | 到下一边界，等待用户提供真实日期 |
| 启用窗口 | `python Scripts/ce_trade_cycle.py start --date 1884-08-25` | 日期只是示例，必须换成用户确认值 |
| 自动统计推进 | `python Scripts/ce_trade_cycle.py advance --allow-run` | 到下一边界，等待用户提供真实日期 |
| 封存核对 | `python Scripts/ce_trade_cycle.py finish --date 1884-09-01` | 日期只是示例，必须换成用户确认值；间隔不是七天则拒绝封存 |

agent 编排约定：

1. 顺序执行 inspect、selftest、prepare，检查每条命令退出码及 JSON 的 `ok`，失败不进入下一阶段。
2. 执行 seek，通过终端会话等待其结束，不并发发送新的 Run。默认最多等待 180 秒、处理 100 个已知停点。
3. `phase=start_wait` 时通知用户“已停在周起点，请告诉我日期”。用户回报后执行 start，再执行 advance。
4. `phase=end_wait` 时通知用户“已停在周终点，请告诉我日期”。用户回报后执行 finish，再解释四类提交次数、商品量和容量账本核对。
5. 任何未知断点、条件错误、对象/进程变化、漏失事件、条件被外部修改或不确认的 Run 回执，都停止推进并保存证据。不能为了得到非零次数放宽条件。

证据目录 `Output/cycle_count/agent/`；状态文件 `Output/cycle_count/agent_state.json`。状态阶段依次是 `prepared → start_wait → counting → end_wait → complete`。原条件保存在 `originalConditions`，实验结束后仍保留断点与实验，不自动清理或重置。

等待超时不等于游戏已暂停，目标可能仍在运行：脚本**不会为了收尾额外 Run 或 Pause**。当状态文件 `pending.accepted=true` 时，可用 `python Scripts/ce_trade_cycle.py wait` 只读等待新停止；如果 Run 效果未确认，先检查证据，不盲目重发。脚本使用排他 `.lock` 文件防止同一状态文件并发编排；进程异常退出留下锁时，先确认没有脚本仍在运行，再人工处理锁，不自动删除不明锁。

本脚本只适用于已核验的当前 PID 43884 和本次州/商品对象；重启、载入存档、换版本或换目标需重新识别，不能直接复用绝对地址。零次仍有证据限制：原生行不暴露线程限制、尚无真实木材提交的正向命中时必须说明；不把提交次数冒充实际槽位写入次数。边界只读到了调用来源与寄存器，没有读取游戏时钟，日期需要用户确认。

实现方案：[贸易周期自动编排](../superpowers/plans/2026-10-03-贸易周期自动编排.md)。

## 二、统计指标与人员分工

| 指标 | 含义 | 是否等于目标调整次数 |
| --- | --- | --- |
| 周批次入口次数 | 到达 `+131C2B0` | 否，是时间边界候选 |
| 州尝试次数 | 到达 `+11FD5C9` 等决策位置 | 否，包括失败尝试 |
| Refresh 次数 | 候选评分/数量刷新次数 | 否，包括最终不提交的候选 |

| 周前后净变化 | 末值减初值 | 否，增减可能抵消 |

每周分别保存 `add_0/remove_0/add_1/remove_1` 四类次数和商品量。方向 0=进口、1=出口是高可信解释，仍需一次已知方向的实际变化确认；原始记录不只保存中文标签。

已分析路径按州建立条目、多轮选候选并逐州调整，同时维护共享市场和全局账本；不支持直接认定“市场先调整一次，再分配各中心”。监测一个州只能回答该州次数。

手工模式下，助手负责明确指定的 Lua、条件断点添加和只读分析，用户负责 GUI 核对和逐次 Run。自动模式下按文首新分工执行：已授权脚本 Run、比较更新本实验条件并自行读回检查；仍不 Step、改速度或写游戏内存。

## 五、计数方式：目标命中后停下，人工继续

### 方案 A：保留条件，手工逐次记录

这是最小变更方案。每次真实新命中提交点，记录游戏日期/时刻、地址、RCX、RDX、商品 ID、RBP、RBX、线程，确认筛选后对相应四类次数加 1、累计 RBX，再由用户 Run。

同一个暂停现场只记录一次；重复只读采集不加 1。每次新事件使用递增编号。不能仅凭 RIP/RSP 相同自动去重，不同事件可能有相同现场。

### 方案 B：条件累计计数，匹配仍停下

需要用户明确同意修改两个已有条件。下面是操作文本，**本轮未执行，计数条件尚未现场验收**；用户仍逐次 Run。不沿用旧指南无条件 `return false` 的不停下计数方式。

先导出旧实验，仅当 `tradeWatch` 不存在时初始化：

```lua
assert(tradeWatch == nil, 'Export the existing experiment before replacing it')
tradeWatch = {
    table = 0x3A484D9F8E8,
    goodsId = 10,
    addAddress = getAddress('victoria3.exe+11FD93B'),
    removeAddress = getAddress('victoria3.exe+11FAF69'),
    armed = false,
    counts = {},
    raw = {},
    events = {},
    errors = 0,
    lastError = '',
    evaluations = {all = 0, state = 0}
}
return {armed = tradeWatch.armed, goodsId = tradeWatch.goodsId}
```

由用户在两个原生条件窗口中替换为同一段 Complex 文本，检查保存/读回。现有添加 CLI 拒绝同地址，不支持更新，不可重复添加来覆盖。

```lua
local watch = tradeWatch
if type(watch) ~= 'table' then return true end
if not watch.armed then return false end
-- 校验并记录本次求值；无入参，返回是否停下，错误由外层捕获。
local ok, stop = pcall(function()
    watch.evaluations.all = watch.evaluations.all + 1
    assert(RIP == watch.addAddress or RIP == watch.removeAddress, 'Unexpected submit address')
    if RCX ~= watch.table then return false end
    watch.evaluations.state = watch.evaluations.state + 1
    assert(math.type(RDX) == 'integer' and RDX ~= 0, 'Invalid goods pointer')
    local goodsId = readInteger(RDX + 0x10)
    assert(goodsId ~= nil, 'Cannot read goods ID')
    if goodsId ~= watch.goodsId then return false end
    assert(RBP == 0 or RBP == 1, 'Invalid trade direction')
    assert(math.type(RBX) == 'integer' and RBX >= 0, 'Invalid quantity')
    local operation = RIP == watch.addAddress and 'add' or 'remove'
    local key = operation .. '_' .. tostring(RBP)
    local event = {
        sequence = #watch.events + 1, key = key, quantityRaw = tostring(RBX),
        ip = string.format('%X', RIP), tableAddress = string.format('%X', RCX),
        goods = string.format('%X', RDX), goodsId = goodsId,
        threadId = tostring(THREADID)
    }
    watch.events[#watch.events + 1] = event
    watch.counts[key] = (watch.counts[key] or 0) + 1
    watch.raw[key] = (watch.raw[key] or 0) + RBX
    return true
end)
if not ok then
    watch.errors = watch.errors + 1
    watch.lastError = tostring(stop)
    return true
end
return stop
```

计数器缺失或错误要求停下检查；errors 非零、事件与次数不一致时，本周标为不完整。`evaluations.all/state` 只是提交条件求值次数，不是州候选评估次数。不匹配而继续属于原生条件筛选，不是助手调用 Run。

先在正式窗口外验收语法、匹配和错误记录。不要在真实暂停现场手工执行计数条件来测试，否则可能重复计数；合成测试须使用独立局部环境和测试计数器。

Lua 文件经用户审阅后可用 `python Scripts/ce_execute_lua.py --file <审阅过的文件> --output Output/cycle_count` 执行，工作目录为仓库根目录。助手只执行明确指定的文本，本指南没有自动创建这些 Lua 文件。

## 七、导出、核对与零次判据

方案 B 用 `return` 输出，使 Lua CLI JSON 保存数据，而不只依赖 CE 控制台：

```lua
assert(type(tradeWatch) == 'table' and tradeWatch.armed == false, 'Disarm before exporting')
local summary = {}
for _, key in ipairs({'add_0', 'remove_0', 'add_1', 'remove_1'}) do
    summary[key] = {
        count = tradeWatch.counts[key] or 0,
        quantityRaw = tostring(tradeWatch.raw[key] or 0),
        quantity = (tradeWatch.raw[key] or 0) / 100000
    }
end
return {
    summary = summary, events = tradeWatch.events,
    evaluations = tradeWatch.evaluations,
    errors = tradeWatch.errors, lastError = tradeWatch.lastError,
    goodsId = tradeWatch.goodsId, tableAddress = string.format('%X', tradeWatch.table)
}
```

人工补充 B0/B1 日期和时刻，Lua 没有读取游戏时钟。核对事件数等于四类 count 之和，每类 raw 等于对应事件整数和，errors=0。方向内提交净商品量为增加量减减少量，不混成一个总商品量。

若所有提交成功写入且没有其他来源，容量方向账本的净变化应为：

```text
容量值净变化 = 100000 × (-add_0 + remove_0 + add_1 - remove_1)
```

四项为次数，不是商品量。这不是 UI 进出口量公式；零净变化可以伴随多次增减，UI 数量还可能受每容量商品量修正影响。

只有身份、指令和配置可靠，B0→B1 覆盖完整，无错误/丢失/途中禁用，才报告本窗口目标提交次数为零。真实命中尚未正向验收、线程覆盖不明或监控不完整时，附上限制，不将未命中写成已证明的业务零次。

`evaluations.state=0` 可能是九州没有商品提交，不自动说明州未被评估。单次失败候选诊断不能证明整周没有其他尝试。统计 Refresh 或所有州尝试需独立实验，不混入提交次数。

## 八、可选 Write 核对实际写入

- [ ] 协调硬件槽：边界＋两提交通常占三个，诊断断点移除/清理后才安排一个 Write 监控。用户检查配置，不自动删除其他断点。
- [ ] `storage=readQword(table+0x08)`；存在位字地址 `table+0x20+8×(goodsId>>6)`，掩码 `1<<(goodsId&63)`。位有效且存储可读时，槽位为 `storage+goodsId×8`，监控长度 8 字节。
- [ ] 在槽位使用 Find out what writes。地址已限定州/商品，通常无需重复筛选。普通 Write/Access 可设置原生条件，DBVM 特殊模式单独核对。
- [ ] B0 记录写统计基线，B1 读取各指令 Count 增量。与提交暂停模式并用须先验收兼容性，保留实际捕获行为，不声称 Find code 自动继续等于助手 Run。

| 操作函数 | 已知槽位写入位置 |
| --- | --- |
| 增加 `+1027970` | `+1027A01`、`+1027A1C` |
| 减少 `+1027A40` | `+1027AD6`、`+1027AF1` |

同组两个位置是不同分支，按实际命中累计；其他写入单列追溯。存储可能重分配：前后指针不同表明可能漏采，前后相同也不能单独证明途中没有迁移。覆盖不明时仅报告采到的写入。

提交与 Write 不一致时调查中途返回、存在位/存储变化、其他来源及监控方式，不强行令二者相等。不将州、方向、市场、全局表写入相加，同次调整会更新多套账本。

## 九、记录与清理

每周保存：实例/PID/构建、州和商品身份、表地址、B0/B1 日期/时刻、暂停位置、四类次数/商品量、逐次事件、errors、条件原文、前后存在位/容量值/存储指针、可取得的 UI 值、Write 增量、异常入口和完整性限制。

候选诊断与周统计分开归档，记录完整或部分窗口。现实采集时间保存 UTC，用户阅读日期按北京时间解释。

- [ ] 导出后解除 armed，不覆盖旧实验数据。
- [ ] 用户决定清理或保留本实验断点/监控，不动原有断点；影子记录等待 CE 安全清理。
- [ ] 结果分别给出评估、提交、已验证写入和 UI 净变化，不省略证据层级。
