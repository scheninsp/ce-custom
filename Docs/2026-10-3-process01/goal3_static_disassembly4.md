# Goal3：一次贸易更新会调整多少商品，以及增减数量如何确定

本文依据 [第一份反汇编报告](goal3_static_disassembly.md)、已保存的机器码与候选快照，并核对本地游戏配置。此次仅分析本地文件，没有运行游戏测试、继续断点或重新采集现场。下文地址为本次构建的 `victoria3.exe` RVA。

## 1. 直接回答

**不是固定调整“1 个进口商品和 1 个出口商品”。** 每次对一个州尝试调整时，保存的是“最多 1 个增加候选”和“最多 1 个减少候选”，每个候选另有自己的进口/出口方向。一次尝试可能只增加、只减少、先减少再增加，也可能完全不调整。

**同一次上层更新包含多轮尝试。** 每轮重新选择候选，因此一个州可以连续调整同一商品，也可以先后调整多个商品。没有看到“本周选过某商品后就不能再次增加/减少”的去重规则；但减少已有贸易受增加后的保护期等资格条件限制。

数量分两个层次决定：

- **单次实际调整的步长**：增加或减少一个贸易容量单位；对应商品量 `q` 由商品基础交易量和州数量修正计算。
- **一次更新累计调整多少**：由每轮选择结果、操作预算、容量、评分门槛与停止条件共同决定，不是一次把预算全部乘进某个候选。

对“每周”还需保留一个边界：本地配置有 `state_weekly_trades_add` 和每周失败操作扣减参数，支持周调整预算的业务解释；但目前调用链尚未完整证明该任务恰好每周调度一次。以下直接能确定的是**一次 `UpdateStateTrades` 调用内的调整机制**，不能把其内部每轮循环当作一个游戏周。

## 2. 增加/减少与进口/出口是两个不同维度

候选槽位的实际含义：

| 条目偏移 | 存放内容 | 候选如何携带方向 |
| --- | --- | --- |
| `entry+B0` | 增加候选：希望再分配一单位容量的商品 | 候选 `+08` 的方向字节 |
| `entry+F8` | 减少候选：优先考虑释放一单位容量的商品 | 候选 `+08` 的方向字节 |

`+B0` 不是进口专用槽，`+F8` 也不是出口专用槽。

证据见 [准备候选函数](../Output/goal3_static_20261002/function_7FF777E0D540.md)：`+131D693` 调用减少选择函数，将结果写入 `entry+F8`；`+131D6D4` 调用增加选择函数，将结果写入 `entry+B0`。

- [增加选择函数](../Output/goal3_static_20261002/function_7FF777D1B320.md) 遍历商品库和方向 0、1，从两方向的合格候选中选一个最高评分者。末尾 `+122B971…+122B97D` 递增方向字节并与 2 比较，明确不是分别保留一个进口和一个出口结果。
- [减少选择函数](../Output/goal3_static_20261002/function_7FF777D1AC50.md) 遍历已有非零贸易，根据容量表的符号生成候选方向，再选最低评分者。`+122AE7E…+122AE8C` 的符号判断与 `setg` 是其方向来源。

当前保存快照中的增加候选是 `wood`，减少候选是 `fine_art`，两者方向都为 0。这已经足以说明这两个槽位不是一进一出的固定配对。结合 [第二份报告](goal3_static_disassembly2.md) 的短缺奖励和需求缓冲分析，0 对应进口、1 对应出口是高可信解释；本结论本身不依赖对枚举名称的猜测。

因此，条件合适时，同一次尝试可以减少一种进口、增加另一种进口，也可以在出口商品之间调整，或跨方向重新分配容量。实际能否执行仍需通过下文门槛。

## 3. 一次尝试最多做什么

[执行函数 `+11FD470`](../Output/goal3_static_20261002/function_7FF777CED470.md) 先刷新两个候选，再进行容量和评分检查。正常有效商品的主路径可归纳为：

| 单次结果 | 商品容量变化 | 对应商品量变化 | 成功操作预算消耗 |
| --- | --- | --- | --- |
| 只增加 | 增加候选多占 1 单位容量 | `+q_add` | 1 |
| 只减少 | 减少候选释放 1 单位容量 | `−q_remove` | 1 |
| 减少后增加 | 旧商品释放 1，新商品占用 1 | `−q_remove` 和 `+q_add` | 合计 1，不是 2 |
| 没有调整 | 无 | 0 | 按失败/终止分支处理 |

函数中没有对同一候选一次连加若干单位的局部循环；多单位变化来自上层重复调用。表中的“一单位”是容量单位，不意味着一件商品，也不意味着一次调整只涉及一个商品。

普通模式下的主要判断：

1. 若旧贸易评分低于维持门槛 25，可以减少。
2. 容量已满时，若新旧商品不同且新评分**严格大于**旧评分的 2 倍，可以为替换而减少。
3. 没有减少且容量已满，则清空该条目剩余预算并返回，不继续增加。
4. 允许进入增加阶段后，增加候选需达到增加门槛 50，才进入增加路径。

初始化模式把维持、增加门槛乘 0.75。具体评分设计见第二份报告，这些门槛决定是否调整，**不会把本次商品量改成“分数差×数量”**。

指令依据：`+11FD6FD` 检查容量；`+11FD70F` 比较商品；`+11FD7BF…+11FD7CB` 比较替换/维持评分；`+11FD849` 调用减少函数；`+11FD87D` 检查增加门槛；`+11FDA35` 共用成功路径只扣一次预算。

实现上还需区分“代码返回成功”与“商品表确实写入”：增加路径的实际写入受商品有效性及 `goods+40` 标志检查约束，随后仍可能进入成功计数路径。上表描述有效、允许交易商品的正常行为，不能把返回 true 无条件当作成交确认。

## 4. 为什么一次更新能够调整多个商品、同一商品也可多次调整

直接上层 [UpdateStateTrades，`+131C2B0`](../Output/goal3_static_20261002/function_7FF777E0C2B0.md) 为多个州建立条目，之后反复进行：

```text
// 功能：对有预算的州反复选择并尝试调整贸易。
// 入参：本次更新的州条目集合；返回：无业务返回值。
function AdjustEntries(entries):
    repeat:
        移除剩余预算 <= 0 的条目
        为剩余条目重新选择增加候选和减少候选
        anySuccess = false
        for entry in entries:
            result = TryAdjustStateTrade(entry)
            anySuccess = anySuccess OR result
    until anySuccess == false
```

对应指令：

| 位置 | 行为 |
| --- | --- |
| `+131CEE0` | 检查条目剩余预算，剔除非正预算条目 |
| `+131D170` | 调度本轮候选准备 |
| `+131D219` | 对当前条目调用一次调整函数 |
| `+131D21E` | 用 `or r12b,al` 合并返回值 |
| `+131D221…+131D22F` | 按 `0x140` 字节步长继续下一个条目 |
| `+131D27F…+131D289` | 若本轮有成功返回，则跳回外层下一轮 |

这里有三个直接影响结论的细节：

- **每轮都会重选候选**，不是首次选出两个商品后整轮更新一直锁定它们。
- 同一个商品只要下一轮仍然合格且评分最优/最差，就可能再次被选中。数量和市场汇总表的变化又会影响后续评分，因此也可能切换商品。
- 循环条件是这批条目“本轮至少一个成功”。某州一次失败但仍有预算时，如果其他州成功，它还可能在下一轮被再次考虑；若所有州本轮都失败，则即使某些预算没耗尽也结束。

减少选择另有通常为 8 周的增加后保护期。刚增加过的商品可能因此暂时不能被减少，但这不是对重复增加的限制，也不是“一个商品每周只能调整一次”的规则。

## 5. 操作预算决定最多能尝试推进多少次

[条目构造函数 `+11FD230`](../Output/goal3_static_20261002/function_7FF777CED230.md) 的 `+11FD248` 调用 `+12295A0`，将返回整数存入 `entry+00`；结束处 `+11FD362…+11FD364` 再复制到 `entry+04`。

| 字段 | 含义 | 当前保存快照 |
| --- | --- | ---: |
| `entry+00` | 本次初始操作预算 B | 11 |
| `entry+04` | 本次剩余操作预算 | 11 |

预算与容量是不同的量。当前 `state+1D58`、`state+1D5C` 都为 126，支持“容量上限 126、已用 126”的解释；不能把这 126 当作剩余可操作次数，也不能把预算 11 当成商品交易量。

预算扣除规则为：

- 成功路径：减 1；即使一次同时减少和增加，也只减 1。
- 普通失败路径：减 `max(1, round(B×0.2))`，比例乘的是初始预算，不是剩余预算。本次 B=11，则通常扣 2。
- 初始化失败路径：减 1。
- 容量满且不能减少等终止路径：可能直接把剩余预算设为 0。

因此，对于同一个条目、同一次更新，B=11 只意味着成功计数路径至多经过 11 次，不能保证一定发生 11 次实际调整。每次最多有一次减少和一次增加；即使理论上累计涉及 22 个单边操作，也不意味着 22 个不同商品，更不意味着进口、出口各调整 11 个商品。

本地 `game\common\production_methods\11_private_infrastructure.txt` 中，贸易中心生产方式同时提供 `state_weekly_trades_add=1` 和 `state_trade_capacity_add=10`，且位于 `workforce_scaled` 块。这进一步支持操作预算与可占用容量是两个独立机制。本轮没有展开 `+12295A0` 的完整实现，不能据此反推当前预算 11 必然来自 11 级建筑，也没有完成预算计算与每周任务排程的端到端验证。

## 6. 单次商品量 q 如何计算

### 6.1 公式及读取位置

[数量函数 `+122AB50`](../Output/goal3_static_20261002/function_7FF777D1AB50.md) 直接读取商品和州属性：

```text
F = 100000
base_raw = int64(goods + 0x50)
modifier_raw = ReadModifier(*(state + 0x18B0) + 0x10, selector=0x97)

q_raw = max(50000, MulFixed(base_raw, 100000 + modifier_raw))
q = q_raw / 100000
```

常用数值范围的可读形式为：

```text
q = max(0.5, 商品基础交易量 × (1 + 州交易数量修正))
```

实际为五位小数定点运算，乘法需要按机器码截断；不是浮点四舍五入。`+122AB64` 读取 `goods+50`，`+122AB88` 对修正值加 100000，`+122AC24…+122AC37` 用最小交易量截下限并写结果。

该函数的实参中没有候选评分，也没有贸易方向。因此，同一州、同一商品、同一数量修正下，增加与减少使用相同的数量步长，进口与出口也不会因为方向不同而在这个函数中获得不同的 q。

本地生产方式配置提供 `state_trade_quantity_mult=-0.5、0.5、1.0` 等修正，与“基础量乘 1+修正”的结构一致。但 selector `0x97` 到正式属性名的完整注册映射本轮尚未还原；不能只凭当前 q 判定州一定启用了某个具体生产方式。

### 6.2 当前样本与硬木的条件推算

商品基础量可与本地 `game\common\goods\00_goods.txt` 对照：

| 商品 | 本地 traded_quantity | 当前对象/候选证据 | 使用 +50% 修正时的 q |
| --- | ---: | --- | ---: |
| wood（木材，前文称软木） | 10 | 对象 `+50=1000000`，候选 `q_raw=1500000` | 15，符合快照 |
| fine_art（艺术品） | 1.5 | 对象 `+50=150000`，候选 `q_raw=225000` | 2.25，符合快照 |
| hardwood（硬木） | 5 | 本轮未读取硬木对象和候选 | 7.5，仅为条件推算 |

快照来源：[商品对象](../Output/goal3_static_20261002/fields.json)、[条目与候选](../Output/goal3_scoring_20261002/constants_snapshot.json)。两组已见样本都符合有效数量修正 +50%：

```text
木材：  1000000 × (100000 + 50000) / 100000 = 1500000 → 15
艺术品： 150000 × (100000 + 50000) / 100000 =  225000 → 2.25
硬木：  若 base_raw=500000 且修正相同，则结果为 750000 → 7.5
```

前两项的基础量和 q 已从快照核对；修正 +50% 是结合函数公式进行的推断，并非本轮直接读取 selector `0x97` 得到的结果。

### 6.3 执行时加减的是 q，不是 1 件商品

增加路径 `+11FD8EA` 读取 `entry+E8`，也就是增加候选 `+38` 的 q。随后：

- `+11FD91D…+11FD93B` 向带符号容量表加 `+100000` 或 `−100000`，代表该方向多分配一单位容量。
- `+11FD940…+11FD974` 向所选方向及汇总商品表加 q。

减少路径 `+11FD83B` 读取 `entry+130`，即减少候选 `+38` 的 q，再调用 [减少函数 `+11FAF20`](../Output/goal3_static_20261002/function_7FF777CEAF20.md)：从容量表减去该方向的一单位，并从相应商品数量表减 q。

容量表用符号编码方向，因此方向 0 增加贸易时，带符号容量值可能变得更负，但实际该方向商品交易量仍增加。不能把容量表数值的加减直接当成进口数量的加减。

执行函数还更新 `q×贸易优势` 的加权汇总表。该加权值与直接商品数量不是同一字段，不能将 q 再乘优势值作为实际增加件数。

## 7. 如何理解累计数量和当前断点

只统计这条逐次调整路径对某州、某商品、某方向的数量增减：

```text
累计变化 = 所有已实际执行增加操作的 q 之和
         − 所有已实际执行减少操作的 q 之和
```

若这些操作期间 q 不变，则简化为 `(增加次数−减少次数)×q`。例如，木材连续成功增加 3 次，量增为 45；艺术品成功减少 2 次，量减为 4.5。这是条件示例，不是本次游戏运行记录。

一次用木材替换艺术品时，若其他条件允许，变化可以是木材 +15、艺术品 −2.25。两边各对应一单位容量，商品数量不必相等，也不要求价值相等。

但**当前保存断点并不满足这次替换条件**：

```text
已用容量 = 上限 = 126
减少候选评分 = 61.28133，未低于 25
增加候选评分 = 99.21745
2 × 61.28133 = 122.56266 > 99.21745
```

所以按该快照静态推演，这一次调用会清空该条目剩余预算并返回 false，而不是实际增加 15 木材、减少 2.25 艺术品。`q=15/2.25` 表示“若执行该候选，单次使用多少量”，并不表示它已经发生。

对硬木同理：如果单次 q 确实为 7.5，数量 330 可以与 44 单位容量相容，但不能据此认定当周执行了 44 次增加。它可能是以前多次更新累计保留的存量分配；要确认还需读取硬木容量表和相应数量口径。

上面的求和只描述本次已展开的调整路径。任务前后还有准备、收尾批处理，界面也可能涉及不同汇总范围；它不是“任何情况下每周 UI 数字差值”的完整公式。

## 8. 已确定的结论与尚未闭合的部分

| 问题 | 当前结论 |
| --- | --- |
| 是否每周固定调整一个进口商品、一个出口商品？ | 否。槽位按增加/减少划分，单次上层更新可多轮处理。 |
| 每次尝试固定同时增减吗？ | 否。可只增、只减、先减后增，或不动。 |
| 同一商品一次更新只能调整一次吗？ | 未见这种限制；每轮重选，资格允许时可重复。 |
| 单次量由评分高低直接决定吗？ | 否。评分用于选择及门槛，q 来自商品基础量和州数量修正。 |
| 同一更新累计调整量如何确定？ | 实际操作次数与各次 q 的累加，受预算、容量、资格、评分及停止条件约束。 |
| 当前为什么不一定发生增减？ | 容量已满，旧候选不够差，新候选也未达到替换倍率。 |
| 是否已证明精确每周排程及预算 11 的完整来源？ | 尚未；需要继续展开任务排程和 `+12295A0`。 |

最准确的描述是：**贸易更新按州分配操作预算，在多轮循环中重选增加/减少候选，每次按一单位容量对应的商品量尝试调整，直到预算或其他停止条件阻止继续。**
