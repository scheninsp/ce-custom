# Goal3：贸易增加、减少评分的静态还原

分析日期：2026-10-02（北京时间）。本文承接 [第一份反汇编报告](goal3_static_disassembly.md)，专门回答“低评分贸易减少、高评分贸易增加”的评分是如何计算的。

## 1. 主要结论

**增加与减少使用同一个评分框架，评分代表保留或扩张该方向贸易的吸引力。增加选择高分，减少选择低分；减少评分并不是“减少能赚多少”的反向收益。** 两种模式在模拟数量、收益与短缺时有所不同。

在通过数量限制后，常用数值范围内可概括为：

```text
单位净收益 p = 税补前价差 ΔP + 商品基价 C × 本方向补助率 U
                              - 商品基价 C × 本方向关税率 T

基础收益 R = 单个贸易容量单位的商品量 q × p

原始评分 D ≈ R
             - 25 × max(T, 0)
             + K × (100 × U - 100 × U反向)
             - 1000 × 反方向市场份额
             + 300 × 短缺指标 H
```

其中 `K` 通常为 1，仅在特定“市场没有供给”的进口条件下为 20。实际运算是五位小数定点运算，各乘除步骤分别截断；上式便于理解，不应直接用浮点合并计算替代原程序。

这说明：

- **收益按一次容量调整所对应的商品数量计算**，不是只比较每件商品利润，也不是整条贸易的总利润。不同商品的 `q` 不同。
- 关税和补助具有两层作用：先影响真实收益，再独立影响贸易意愿评分。反方向补助只在额外评分项中扣分，本方向净收益计算没有直接减去它。
- 同一市场已有较多反方向贸易时会被扣分；数量关系过于不合理时，直接将评分设为最小整数。
- 短缺会提高进口的保留或增加意愿。对减少候选，短缺指标考虑移除一单位之后的供给。
- 随机性主要影响选择谁成为候选；最终执行前重算原始评分，再检查维持、增加与替换门槛。

以上运算与分支可由指令还原。`ΔP` 内部的完整市场定价公式，以及部分商品表的正式名称，仍没有全部展开。本文不会把这些部分写成已恢复的源码。

## 4. 基础收益：数量、价差、关税、补助

### 4.1 增加与减少的模拟方式不同

`+11FC080` 在模式 1 时复制 8 张商品表组成的 `0x280` 字节上下文，并加入 `q`：

| 模式/方向 | 收益计算所用上下文 |
| --- | --- |
| 增加、方向 0 | 临时上下文 `+00` 与 `+140` 的该商品表项各加 `q` |
| 增加、方向 1 | 临时上下文 `+50` 与 `+190` 的该商品表项各加 `q` |
| 减少 | 使用原上下文，不先减去 `q` 再算价差 |

因此，**增加评估的是再增加一单位后的单位收益；减少评估的是现有贸易的收益**。后者的短缺评分会另行模拟减少，不能把这两个步骤混为一谈。

### 4.2 价差与单位净收益

`+140A6B0` 调用本地/州相关价格函数 `+1408330`，再经 `+13A3280`、`+13A3B10`、`+13A5280` 生成另一个价格侧，并调用 `+1726A10`、`+1726AF0` 获取上下界进行限制。末尾明确按方向求差：

```text
方向 0：ΔP = A - P
方向 1：ΔP = P - A
```

`A` 为 `+1408330` 的输出，`P` 为另一价格侧经乘法及上下界限制的结果。将 `A` 解释为本地/市场价格、`P` 解释为有效世界市场交易价格是高可信推测；其内部优势修正、价格曲线尚未完整还原。不能把它直接替换为界面所显示的两个裸价格。

`+1207860` 则明确还原为：

```text
C = max(1, signed_word(goods + 0x44))
p = ΔP + MulFixed(C, U) - MulFixed(C, T)
R = MulFixed(q, p)   // 最后一步位于 +11FC080
```

软木 `goods+44=20`、艺术品 `goods+44=200`，与本地 goods 配置的 `cost` 一致，支持 `C` 为商品基价。

`+1206D40` 的普通路径把方向性州修正与商品专用关税修正相加，再乘政策等级倍率；`+1207370` 取方向性补助修正并乘政策倍率。对应级别倍率为 0.25、0.5、1；不属于相应政策类型时为 0。两函数对特殊州标志 `+11B8` 返回 0，并引用 `TREATY_PORT_NO_TARIFFS_OR_SUBVENTIONS`，支持条约港免税补的解释。

配置中的 `AUTONOMOUS_TRADE_POTENTIAL_REVENUE_BASE_COST_FACTOR=0.25` **未在本轮已展开的评分主体中识别到直接使用**，不应因为它与其他系数相邻，就把 `R` 再除以 `C×0.25`。更深层未展开函数是否使用它，仍需另查。

## 5. 评分前置数量限制与反向份额

### 5.1 先检查是否应该完全排除

`+11FC8BE…+11FC97D` 计算：

```text
若 L > MulFixed(W - O, 2)：
    D = INT64_MIN
    返回
```

这里的 2 对应运行时 `7FF77C379D10=200000`，与配置 `BUY_SELL_DIFF_AT_MAX_FACTOR=2` 相符。比较是严格大于，等于时继续。

结合后面的反向份额项，可将 `W` 理解为相关世界反方向总量，`O` 为本市场反方向量，`L` 为本市场当前方向量（增加模式含新增 `q`）。业务含义是：本市场的贸易量不应超过市场外对向可承接量的两倍。该解释的可信度高于各表正式成员名称。

为了避免靠命名猜公式，下面给出精确来源。`M[a]` 表示市场对象偏移 `a` 开始的商品表中本商品的值，`G[a]` 表示全局贸易对象对应表值，`X[a]` 表示传入上下文对应表值。各表按有效位图读取，未出现时为 0；`I=1` 仅在增加模式成立。

| 方向 | W | O | L |
| --- | --- | --- | --- |
| 0 | `G[5A8] + X[140]` | `M[2D8] + X[F0] + X[00]` | `M[288] + X[A0] + X[50] + I×q` |
| 1 | `G[558] + X[190] + MulFixed(q,10)` | `M[288] + X[A0] + X[50]` | `M[2D8] + X[F0] + X[00] + I×q` |

所有偏移均为十六进制；如表对象 `G[558]` 的数值数组指针在 `G+560`。全局对象来自 `[[GameState+608]+120]`，其中 `GameState` 在本次代码中取自全局指针 `7FF77C3A8A50`。

方向 1 的 `10×q` 对应 `WORLD_MARKET_GOODS_DEMAND_BUFFER=10`。配置注释说明它用于给新商品提供世界市场需求，使首个出口者有机会获利。这是出口侧的特定需求缓冲，不是所有方向通用的评分平滑项。

### 5.2 通过限制后仍有反向份额扣分

当 `W>0`：

```text
share = DivFixed(O, W)
评分增加 MulFixed(share, -1000)
```

`W<=0` 时跳过这一项。指令区间为 `+11FCD7A…+11FCEC2`。

例如反向份额为 1% 时约扣 10 分，5% 时约扣 50 分。这表达的是对同市场双向贸易的抑制，并不等于该州贸易占世界贸易的份额，也不是 `L/W`。上面的严格数量限制与此处连续扣分是两个独立步骤。

## 6. 关税、补助及新商品倍率

`+11FC982` 从 `candidate+10` 取基础收益，之后顺序累加：

```text
score = R
if T > 0:
    score -= MulFixed(T, 25)

bonus = MulFixed(U, 100) - MulFixed(U反向, 100)

if bonus > 0 and direction == 0:
    S = GetSupply(candidate, context)  // +11FD0D0
    if (mode == 1 and S <= 0) or (mode == 0 and S <= q):
        bonus = MulFixed(bonus, 20)

score += bonus
```

证据区间：关税 `+11FC9E5…+11FCA9D`，两方向补助 `+11FCAF8…+11FCC8E`，新商品判断与倍率 `+11FCC91…+11FCD77`。

几个容易误读的点：

- **20 倍放大的是正的补助差评分项，不是整个评分，也不是净收益。** 补助差不为正时不放大。
- 增加模式要求现有有效供给 `S<=0`；减少模式要求 `S<=q`，即移除本次量后可能无供给。后者会倾向保留最后一批进口供给。
- 负的补助差照常扣分，没有截为零。
- 25 和 100 乘的是有效税补率，如 10% 使用 0.1；没有再乘当前总贸易数量。
- 收益部分已经计算 `C×U` 与 `C×T`。这些额外分项可以理解为对贸易政策的行为偏好，是在经济收益之外再次施加的激励。

## 7. 短缺奖励的具体曲线

`+11FBA60` 只处理方向 0，且市场 `M[188]` 的该商品值必须大于 0。该表起到资格门槛作用，正式成员名尚未确认，不应忽略这个条件。

两个辅助函数的数据流为：

```text
B = M[1D8] + X[50] + X[A0]   // +11FCF70，需求/买单，高可信
S = M[228] + X[00] + X[F0]   // +11FD0D0，供给/卖单，高可信

若 mode == 0：S -= q
```

见 [需求读取](../Output/goal3_scoring_20261002/function_7FF777CECF70.md) 和 [供给读取](../Output/goal3_scoring_20261002/function_7FF777CED0D0.md)。

当前参数 `threshold=0.5`、`maxPenalty=0.5` 下：

```text
不满足方向/资格条件，或 B <= 0：H = 0
否则 S <= 0：                 H = 0.5
否则：
    ratio = DivFixed(S, B)
    H = clamp(1 - DivFixed(ratio, 0.5), 0, 0.5)

评分额外增加 MulFixed(H, 300)
```

例：供需比 0.5 或以上，加 0 分；0.4 时约加 60 分；0.25 或以下最多加 150 分。零供给在这条评分路径也取 0.5，不能套用其他系统的 `GOODS_SHORTAGE_PENALTY_MISSING_INPUTS=0.75` 算成 225 分。

减少模式使用 `S-q`，所以当前尚不短缺的贸易，移除后如果触发短缺，也会得到更高保留评分。增加模式的短缺项使用原上下文的 `S`，并不像收益部分那样预先加 `q`；这是代码中的实际不对称。

## 8. 随机选择与最终执行

### 8.1 扰动公式

两个选择函数在 `D>0` 且随机系数 `f>0` 时，都使用两个连续伪随机取样：清除符号位，再对 100000 取余，得到五位定点的 `u,v∈[0,1)`。

```text
D选择 = DivFixed(
    MulFixed(D, 1 + MulFixed(f, u)),
    1 + MulFixed(f, v)
)
```

本次 `f=0.5`，忽略末位截断时，乘数大致在 `2/3` 到 `1.5` 之间。不是简单的 `D±50%`，也没有证据支持把所得乘数视为均匀分布或称两个取样完全独立。

增加函数的核心证据是 `+122B552…+122B8E0`：先算 `f×u`，加 1 后乘评分，再以 `1+f×v` 作分母。减少函数对应区间为 `+122AEC0…+122B257`。

### 8.2 选谁与是否执行是两件事

| 阶段 | 减少 | 增加 |
| --- | --- | --- |
| 候选范围 | 已有非零贸易，通常需经过增加后 8 周保护期 | 两方向商品库，经过国家/市场、现有方向等过滤 |
| 初始评分 | 共用 Refresh，模式 0 | 共用 Refresh，模式 1 |
| 选择前门槛 | 不要求已经低于维持门槛，先找相对最低者 | 原始评分先通过增加门槛，才接受随机扰动 |
| 排序 | 扰动后的最低分 | 扰动后的最高分 |
| 同分 | 使用伪随机位决定是否替换当前候选 | 同样使用伪随机位 |

执行函数在 `+11FD59D`、`+11FD5B6` 分别 Refresh 减少与增加候选，覆盖选择阶段的随机评分。当前断点 `+11FD5C9` 已在这两次刷新之后。

普通模式下关键门槛为：维持 25、增加 50；初始化时两者乘 0.75。满容量换商品还要求商品不同，且 **新评分严格大于旧评分的 2 倍**；旧评分低于维持门槛时也可减少。2 倍是替换阻力，不是评分函数本身的倍率。

所以，“被选为可减少候选”不等于下一条指令就会减少。它可能只是现有候选里最差的一项，仍然值得保留。算法也没有证明在求所有贸易的全局最优组合，更像带保护期、预算、随机选择和替换门槛的逐次调整。
